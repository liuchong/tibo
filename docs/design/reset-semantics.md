# 重置公告语义识别与可靠恢复

自然语言由 AI 判断对象、语气、承诺、否定、延期、兑现和前后关联。程序核对官方作者、原文引用、时间顺序及结构，使用独立的历史与时间模型计算数值。关键词规则用于暂定线索和无 AI 的数值降级，不能否决已核对的语义事实。

## 一致的证据

否定所修饰的命题分别解释：否定已完成不等于撤回未来承诺。

原帖按发布时间去重排序，使用短 ref 对应永久原文；窗口成员由程序提供。顶层最后确认与六个发言窗口共用同一个已确认重置边界，另有官方资料窗口。所有七维在一次主请求返回；推文断言和资料断言分开。产品上线和额度发放的对象、状态分别提取，不能只根据“完成”一词确认重置。

上下文引用按本次观察时间 now 限定，而不是限制为被解释原帖发布之前：同一次采集已看到的后续本人回复可以补充早先公告的期限。断言仍保留原帖发布时间，后续说明仍保留自己的来源；超出观察时间的原文和引用拒绝，历史前缀回放不使用事后信息。语义缓存同时绑定服务、模型和凭据身份，切换模型后不沿用旧模型的待核对缓存或冷却；此前落库的已确认事实继续保留。

主响应为 `dimensions`、`postClaims`、`documentClaims`。各个维度、断言和引用独立校验：一个越界引用不能清空另一条正确完成事实。对应维度失效后使用本地维度，保留诊断，不通过删除引用保留原分数。AI 语义判断不再次经过词表过滤。程序保存原文跨度、对象、状态、上下文关联及版本，不把语义关联伪装成官方 parent/quote。

明确的午夜期限按日历时间解析：`by midnight PST/PDT/PT` 是发帖当地日期结束的 24:00，`tomorrow` 再前进一日，复用已有时区换算；它属于期限而不是完成公告，不移动 global 时钟。

## 交叉核对与有限恢复

完整七维主分析后，用另一套事件链提示词核对近期完整消息批次，能发现主分析漏掉的承诺或完成；不是只复核已识别的候选。输入按UTF-8字节保守上界970000计量，主输入超限时保留全部本地窗口，有限事件核对仍可使用紧凑输入；不会无限增加请求。

关键 global 承诺、完成和撤回需要两种视角的对象、状态及证据关联一致。出现分歧或失败时，再用第三种简化结构进行独立裁决。多数结果仍须通过来源与引用检查，不把分类结论机械平均成概率。

每批最多三次实际尝试，总时限60秒，每次不超过20秒；包括核对、超时、格式错误及裁决，不存在嵌套的三倍重试。认证、余额和限流等错误按类别结束本轮并遵循服务冷却。结构失败换更明确的结构，已接受的断言继续保留。冷却和缓存持久化，按证据与语义策略合并并发，同一未变化证据一小时内最多尝试三次；成功结果持续复用，证据、引用关系、窗口成员或策略变化使结果失效。

七维评分请求与事件链核对使用不同契约和功能冷却，旧格式错误不会阻断新契约。诊断保留错误字段、固定错误码、调用状态及耗时；不把上游响应和内部环境发送到 IM。其他 AI 任务沿用网关的请求准入、诊断、缓存及错误隔离，不无差别增加多次语义核对。

## 事件事实与预测一致性

经核对的完成公告通过唯一对账入口写入运行 ledger，`completionBasis=semantic-evidence-agreement`，保存原文引用和核对数。`at` 为完成公告发布时间，不猜测更早的账户交割时刻。重复传播公告通过所指事件去重，原文各自保留。

事件和 `pendingConfirmations` 在同一事务写入，通知搬运按事件ID幂等，崩溃后继续。确认后重新计算历史、等待时钟、七维窗口及旧信号消耗，使旧预测和用卡建议失效。CLI、实时监测和聊天使用同一份事实，不能只有一份报告知道已经完成。

期限经过只表示预告过期，不能产生已完成 global 或 verified 事件。既有推定交割不参与确认时钟。AI 暂时不可用时，历史和时间模型继续输出24h/48h数值，最新消息标记语义核对待完成；不能把分析失败描述成作者没有兑现。在线规则新发现的事件为暂定记录，等待语义对账；已核对安装历史和此前确认事实继续保留。

## 验证

回归包含真实承诺—期限—完成序列，以及明确标注为构造的否定、反讽、跨句祝语、产品发布、banked、部分用户和延期文本。按输入时间前缀回放，避免使用事后信息。分别记录结构合格、有效断言保留、完成误报/漏报、承诺识别及延迟/token；同时验证事件落库、重启恢复、缓存、数值降级和通知队列。真实API探针与隔离系统测试分别留存，测试替身不代表实际IM送达。
