# IM 触发、相关度与回复节奏

这是核心策略，不是 Lark 专属业务。适配器提供已认证的正文、本人身份、会话与稳定事件 ID。核心分开判断触发级别、内容相关度和是否适合此刻回复：敏感词被判定相关，不代表机器人必须开口。群白名单、操作者类型、平台时效与管理权限先核对。私聊、CLI 和 MCP 不使用群内插话预算；群里点名和祈祷也遵守独立的群回复上限。

Lark 被动群范围默认 `all`，也可使用显式列表或空值。它只决定普通交互入口，不能赋予管理员权限或自动订阅群通知；操作群与群订阅独立配置，见 [会话接入与通知边界](conversation-access.md)。

## 一级强触发

优先级从高到低：

1. 文字含 Unicode 🙏 或 Lark 原生“双手合十”，记录一次上香；不吞掉同条消息的另一项业务意图。点击平台的 🙏 反应同样上香。
2. @ 当前机器人，或者文字任意位置包含 tibo（大小写不限），直接进入正常业务/智能处理。开头的 tibo 称呼被去掉；只有称呼时显示帮助。
3. 私聊消息无需额外关键词。

“直接进入智能逻辑”复用原有命令与角色路由，不强迫每次经过通用 ask 模型：明确固定命令仍直接执行，概率查询进入预测，Claude 问题进入角色，其他自然语言使用语义路由。正文不会被改写成系统命令。

强触发不经过次级相关度，但仍经过群回复预算。上香自己的 15 秒功德冷却与请求去重照常生效；被回复预算抑制时仍记录上香、成就和会话愿力，但不发送回执、不生成 AI 祝词，可私聊或稍后用 pray me 查档案。普通查询正文最多 800 字；含 🙏 的长正文仍可上香，素材独立截断。

同条文字同时包含祈祷和命令、点名问题或相关关键词时，去掉祈祷符号后独立识别正文，例如 `help 🙏`、`🙏 posts 2 |translate ja`、`tibo 预测 🙏`、`Claude编程模型难用 🙏`。明确固定命令无需再 @，其余正文沿用点名、私聊或次级相关度规则。纯祈祷、只有称呼、重复的 `pray` / `上香` 不额外查询；无关群话题只上香。祈祷的完整原消息仍保留为祝词素材。

复合事件解析后，上香与正文分支通过核心 `im/tasks.run-tasks` 同时启动，各自记账、判断、执行和发送，谁完成谁立即回复，不规定先后，也不等待另一项生成或发送。上香分支先持久记录再生成祝词；正文无需等待上香记账。各分支有稳定的去重键与投递账本，一项失败不取消另一项；根事件等分支全部结束后才确认处理完成，等待仅用于收件箱结算，不汇总或缓存回复。

两项回复分别遵守原有预算，最多各一条常规回复，庆典另按原规则处理。同一原消息的祈祷回复不会触发正文的“其他对话正在进行”抑制，但两项都计入群与个人文字总量。祈祷冷却不会阻止正文命令，正文被相关度或预算过滤也不会丢失上香；管理命令仍检查管理员、操作会话与二次确认。重投或重启只处理缺失分支，不重新执行已经有处理记录的命令或重复上香。表情回应仍落在原消息上，匿名上下文也以原消息定位。

点击已有消息的 🙏 反应只记录点击者上香并取原消息作素材，不执行该消息里他人或过去的命令。它不是一次新的正文命令输入。

上香入队后先持久记账，再决定是否回复。集体彩蛋按会话的实际上香次数解锁，限频时保留未展示彩蛋，下次允许回复的上香只展示一次，不补发旧祈祷；具体规则见 [上香](pray-subscriptions.md#集体彩蛋与快速连发)。

## 二级次级触发

群聊中未点名的正文使用次级检测，包括同时含祈祷的另一项正文意图。初始关键词和相关度门槛：

| 关键词 | 门槛 |
| --- | --- |
| claude，克劳德，克洛德 | 0.50 |
| anthropic | 0.62 |
| openai | 0.68 |
| gpt / ChatGPT / GPT 版本名 | 0.70 |
| 重置 / reset | 0.76 |

这些是启发式响应门槛，不是统计校准后的概率。Claude 较敏感；重置需要较明确的 Codex、额度或 AI 上下文。关键词出现不等于立即回复。

本地先识别明显无关语义，例如 Claude Monet 画家、GPT 磁盘分区、路由器或密码重置；不进入队列、不调用模型。其余候选结合模型/编程、Codex/token/额度、比较/求助等上下文计算分数。隐私配置类问题不上传模型。

高于当前门槛 0.15 的明确话题由本地放行。没有明确话题、但至少一个关键词分数在门槛下方 0.15 以内时，启用 trigger 可用短模型判断；只返回各关键词的 0..1 scores，最多 120 输出 token、预算 1.2 秒，无回答、命令或执行工具。模型关闭、不可用或输出错误时回退本地相关度。没有接近门槛的话题不为分类调用模型。

通过相关度之后仍须取得独立文字回复预算，才能进入正常语义/角色/业务处理；未通过不发送拒绝提示。部分本地弱关联可按下节规则加表情，AI 判为不相关则保持安静。模型不决定管理员权限或回复次数。

## 三级低优先级与轻量表情

Codex、token / 上下文、额度 / 限流、agent / 智能体、AI 编程 / 大模型增加为三级候选。仅出现这些词不触发文字回答；结合本条正文计算本地相关度，不为三级分类或表情调用模型。房地产 agent、JWT / 区块链 token 等无关含义排除。消息同时包含二级关键词时仍按二级；含 🙏 或点名仍优先一级。

“重置 / reset”仍是二级关键词；“重置了 / 重置啦 / reset landed”等完成语气增加本地相关度，但不是已核实事实，真正的重置状态仍取自采集。密码或路由器重置继续排除。

三级候选、二级本地分数中等但未到文字门槛的消息，以及通过相关度但主动插话预算不足的消息，可以改为表情。点名后的普通只读查询被文字限频时也可收到表情，未识别的自然语言仍须本地相关度达到 0.60。固定只读命令可以直接轻量确认收到，不再为此调用 AI。AI 已判为不相关、敏感信息、悲伤事故及超时主动消息不加表情。管理、订阅变更、祈祷及重复点名请求不走这条替代路径。选择是固定程序规则：品牌轻松话题用 SMILE，发布话题用 THUMBSUP，其他用 OK；不让 AI 返回任意 emoji、消息 ID 或接口。表情仅表示收到，不表示查询、订阅或管理操作已经执行，不给出概率和额度事实。

表情使用独立容量，不占用文字额度，也不要求文字额度尚有空位。每群、同人、同关键词的间隔均为 5 秒，每分钟最多 12 个，同人每 10 分钟最多 10 个。群十分钟额度随最近两分钟实际收到的人类消息量调整：不足 12 条为 20 个，12..29 条为 25 个，30 条及以上为 30 个。群聊转冷时立即使用较低额度，已发送数量不会清零；额度是上限，不是要补满的目标。文字预算照常保留。表情不会追加文字，不替代祈祷记账，不在冷却后补发旧消息。接入层不支持表情时保持静默。

每条原消息默认只选择一枚表情，按原消息 ID 的持久回执去重。群变活跃、队列重投、冷却结束或进程重启都不会向同一条消息追加第二种表情；更多额度用于回应更多不同消息。只选现有三个固定表情之一，不轮番全点，也不会堆积十几种表情。

Lark 使用固定 react 方法和原消息 ID。发送前写回执；重投不重复添加，结果未知不重试。接口失败暂停该应用的表情能力 10 分钟，错误只保留本地状态，不向群发送权限或供应商错误。其他文字、上香和查询继续工作。所需权限见 [Lark 接入](lark.md)。

## 连续讨论降敏

按 transport + account + scope 隔离群话题状态，使用消息指纹，不存正文或身份。跨群互不影响，同群不同人的同类话题共用降敏，防止多人接续刷屏。

- 每次同关键词候选使门槛增加 0.10，最多增加 0.30，最终不超过 0.97；不相关与被降敏的候选也会记录讨论频次。旧记录在五分钟窗口之外不再影响门槛。
- 稳定事件 ID 保存判断结果，平台重投不重复调用模型；每个会话状态最多保存 128 条命中和 128 条判断。

相关度模块不再用旧的 20 秒/60 秒冷却来代替回复节奏。明确相关的连续讨论可以仍被判定相关，再由下述预算抑制。预算不足时只更新本地相关度与降敏记录，不调用分类或回复模型。相关度状态损坏、锁忙或不可读时只安静忽略次级触发，不影响点名与祈祷的业务识别。

## 独立的群回复预算

预算按 transport + account + scope 隔离，按平台 actor 的摘要限制个人，不以昵称分配。只计算机器人已预留或发出的回复，不把其他人的发言算成机器人回复。滚动窗口使用实际时间；换人说同一个关键词、程序重启都不能重开预算。

| 情形 | 默认限制 |
| --- | --- |
| 群内全部文字交互回复 | 每分钟最多 6 条，每 10 分钟最多 24 条；表情另计 |
| 同一个人在同群得到的文字交互回复 | 每分钟最多 3 条，每 10 分钟最多 10 条；表情另计 |
| 未点名的关键词主动插话 | 同群至少间隔 2 分钟，每 10 分钟最多 2 条，每小时最多 6 条 |
| 同一个人的主动插话回复 | 每 5 分钟最多 1 条，每小时最多 3 条 |
| 同一关键词讨论 | 主动回复至少相隔 5 分钟，不因换人而绕开 |
| 群最近两分钟已有 12 条人类消息 | 主动回复间隔增加到 4 分钟，给繁忙讨论让路 |
| 已经回应点名或祈祷 | 接下来 45 秒不主动插话；新的点名仍走交互预算 |
| 重复正文 | 主动讨论同文 10 分钟不重复；同人点名同文 30 秒不重复 |
| 同一个人祈祷 | 群回执至少相隔 15 秒；每次新事件仍计数 |

点名无需服从主动插话的低频额度，但仍不能突破群与个人文字总量。超过文字预算不发“限流了”提示；相关讨论和普通只读查询可申请独立表情预算，两种预算均不足时静默。点名请求尚未执行，不会创建管理票据或改变配置，也不因加了表情就重新执行查询。祈祷是例外：先按原有幂等请求键记档，再静默消费事件，不因关闭 AI 或限频丢失计数。

先做便宜的本地预算预检，再判断相关度，最后原子预留发送名额。并行快捷/普通队列不能各自拿到一份额度；同进程的会话事务排队，跨进程仍使用文件锁。确认发送成功后记为 sent；结果未知仍占名额，只有明确拒绝或确定尚未发出才释放。状态不可读时不冒险刷屏，祈祷记档路径仍独立执行。

被抑制的消息不排队补发，也不会在冷却结束后一次性吐出历史回复。排队超过 90 秒的主动插话直接消费为 ambient-expired。北京时间 09:00/21:00 的共享定点推送走独立分发，不使用交互预算，也不会因订阅人数变动生成更多报告。

## 群活动缓冲与对话历史

授权群的短期观察仍用于相关性和回复频率计算：每群最多 48 条脱敏消息和 128 条活动记录，十分钟之外在后续事件中清理。它不会作为无引用问答或管道的 AI 聊天历史，不影响命令权限和预测证据。

只有用户明确引用/话题回复时，接入层按该 Thread 读取并持久积累对话；完整导入、追加轮次、容量摘要和回复方式见 [基础聊天与引用对话](chat.md)。当前问题最重要，历史不作为时事证据或可执行指令。

## 祈祷的消息素材

文字上香将该条正文作为素材；表情反应读取被点击的那条消息，不只限于本机器人消息。平台可读且会话授权才会计数；不会主动读取群历史或相邻聊天。不能读取的陌生消息不凭空推测会话，也不会记录上香。

Lark 使用固定只读 messageInfo 方法，最长等待 1.8 秒；本机器人新回复已有脱敏缓存时不额外读取。老回执无素材时可补读；私聊会话类型无法从回执确认时另用固定 chatInfo 核实。读取成功不是扩大会话白名单的依据。

素材先经过公共隐私过滤，移除身份 ID、邮箱、手机号与香客编号，涉及密钥/系统环境类内容则舍弃；最多 500 字，只有 material 字段进入 wish，不上传 actor、account 或群名。纯 🙏 没有额外素材。素材影响比喻与祝愿主题，不能变成指令、事实判断、厂商比较或实际额度操作；祝词本质和校验仍按 [神谕约定](oracle.md)。

正文素材参与缓存键，因此不同心愿可得到不同祝词，相同素材/场景/随机变体仍可共享 20 分钟缓存。先记账再生成、1.5 秒预算、本地兜底与重复请求不再生成仍然有效。

## 生命周期与诊断

关键词扫描在接收阶段本地完成。次级模型过滤在普通 inbox 工作队列执行；先持久化候选再 ACK，不在 WebSocket 回调等待模型。三级只做本地判断。🙏、help 和订阅仍使用快捷队列。

相关度忽略记录 state=filtered、reason、method；回复预算抑制记录 state=suppressed、replyPolicy 和 prayerRecorded。复合事件根记录 state=handled，receiptKey 指向祈祷分支，companionReceiptKey 指向正文分支，须读取各分支核对实际结果。below-threshold、unrelated、filter-unavailable 是相关度原因；room-budget、person-budget、ambient-budget、ambient-spacing、topic-spacing、busy-room、direct-conversation、prayer-spacing 等是独立回复策略原因。账本不记录正文，按已消费事件去重。events.accepted 表示任务入队，不等于机器人发了消息；成功投递的 latency 还记录回复策略与采用的上下文条数。

表情成功回执为 reacted；失败或未知为 reaction-unavailable-or-uncertain。它们与文字 sent 分开，不把事件入队当作已经回应。实现：src/im/triggers.eli 负责相关度；reactions.eli 负责轻量表情选择；reply-policy.eli 负责文字和表情预算；context.eli 负责短窗口；serial.eli 负责同会话事务；src/prayer/material.eli 负责祈祷素材。Lark 边界为 service / interaction / inbox / bot。其他 IM 复用这些核心方法，并保留各自的认证、持久收件箱和发送结果确认，不能只复制关键词规则。
