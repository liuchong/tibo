# IM 消息触发与相关度过滤

这是核心策略，不是 Lark 专属业务。适配器提供已认证的正文、本人身份、会话与稳定事件 ID；核心负责触发级别、相关度、连续触发降敏。群白名单、操作者类型、平台时效与管理权限始终在触发之前核对。私聊正常响应全部可处理消息。

## 一级强触发

优先级从高到低：

1. 文字含 Unicode 🙏 或 Lark 原生“双手合十”，直接执行一次上香。点击平台的 🙏 反应同样上香。消息同时提到 tibo / Claude 时仍优先上香，不另外执行查询。
2. @ 当前机器人，或者文字任意位置包含 tibo（大小写不限），直接进入正常业务/智能处理。开头的 tibo 称呼被去掉；只有称呼时显示帮助。
3. 私聊消息无需额外关键词。

“直接进入智能逻辑”复用原有命令与角色路由，不强迫每次经过通用 ask 模型：明确固定命令仍直接执行，概率查询进入预测，Claude 问题进入角色，其他自然语言使用语义路由。正文不会被改写成系统命令。

强触发不经过次级相关度或群话题限频。上香自己的 15 秒功德冷却与请求去重照常生效，冷却时仍记录次数并返回祝词。普通查询正文最多 800 字；含 🙏 的长正文仍可上香，素材独立截断。

## 二级次级触发

只在群聊没有一级触发时检测。初始关键词和相关度门槛：

| 关键词 | 门槛 |
| --- | --- |
| claude，克劳德，克洛德 | 0.50 |
| anthropic | 0.62 |
| openai | 0.68 |
| gpt / ChatGPT / GPT 版本名 | 0.70 |
| 重置 / reset | 0.76 |

这些是启发式响应门槛，不是统计校准后的概率。Claude 较敏感；重置需要较明确的 Codex、额度或 AI 上下文。关键词出现不等于立即回复。

本地先识别明显无关语义，例如 Claude Monet 画家、GPT 磁盘分区、路由器或密码重置；不进入队列、不调用模型。其余候选结合模型/编程、Codex/token/额度、比较/求助等上下文计算分数。隐私配置类问题不上传模型。

高于当前门槛 0.15 的明确话题由本地放行。没有明确话题、但至少一个关键词分数在门槛下方 0.15 以内时，启用 trigger 可用短模型判断；只返回各关键词的 0..1 scores，最多 120 输出 token、预算 1.2 秒，无回答、命令或执行工具。模型关闭、不可用或输出错误时回退本地相关度。没有接近门槛的话题不为分类调用模型。

通过后进入正常语义/角色/业务处理；未通过保持安静，不向群发送拒绝提示。模型不决定管理员权限。

## 连续讨论降敏

按 transport + account + scope 隔离群话题状态，使用消息指纹，不存正文或身份。跨群互不影响，同群不同人的同类话题共用降敏，防止多人接续刷屏。

- 同群次级回应至少相隔 20 秒。
- 同关键词的次级回应至少相隔 60 秒。
- 五分钟内正文相同的候选不重复回应。
- 每次同关键词候选使门槛增加 0.10，最多增加 0.30，最终不超过 0.97；不相关与被降敏的候选也会记录讨论频次。旧记录在五分钟窗口之外不再影响门槛。
- 稳定事件 ID 保存判断结果，平台重投不重复调用模型；每个会话状态最多保存 128 条命中和 128 条判断。

关键词冷却、同文重复与频次门槛在模型调用前处理，已被抑制的消息不消费 AI token。状态损坏、锁忙或不可读时只安静忽略该次次级触发，不暂停正常查询或祈祷。

## 祈祷的消息素材

文字上香将该条正文作为素材；表情反应读取被点击的那条消息，不只限于本机器人消息。平台可读且会话授权才会计数；不会主动读取群历史或相邻聊天。不能读取的陌生消息不凭空推测会话，也不会记录上香。

Lark 使用固定只读 messageInfo 方法，最长等待 1.8 秒；本机器人新回复已有脱敏缓存时不额外读取。老回执无素材时可补读；私聊会话类型无法从回执确认时另用固定 chatInfo 核实。读取成功不是扩大会话白名单的依据。

素材先经过公共隐私过滤，移除身份 ID、邮箱、手机号与香客编号，涉及密钥/系统环境类内容则舍弃；最多 500 字，只有 material 字段进入 wish，不上传 actor、account 或群名。纯 🙏 没有额外素材。素材影响比喻与祝愿主题，不能变成指令、事实判断、厂商比较或实际额度操作；祝词本质和校验仍按 [神谕约定](oracle.md)。

正文素材参与缓存键，因此不同心愿可得到不同祝词，相同素材/场景/随机变体仍可共享 20 分钟缓存。先记账再生成、1.5 秒预算、本地兜底与重复请求不再生成仍然有效。

## 生命周期与诊断

关键词扫描在接收阶段本地完成。次级模型过滤在普通 inbox 工作队列执行；先持久化候选再 ACK，不在 WebSocket 回调等待模型。🙏、help 和订阅仍使用快捷队列。

次级忽略在投递账本记录 state=filtered、reason、method；不记录正文，按已消费事件去重。events.accepted 表示接收任务已入队，不等于机器人发了消息。若没有回复，先看对应账本；conversation-cooling、keyword-cooling、below-threshold、unrelated、filter-unavailable 含义分别是同群冷却、同词冷却、低于门槛、无关和过滤状态不可用。

实现：src/im-trigger.eli、src/prayer-material.eli；Lark 边界：service / inbox / api。后续 IM 复用 trigger-candidate、decide-secondary 与 prayer-material；凭据、会话认证和平台消息读取仍由各自适配器完成。
