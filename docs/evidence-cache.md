# 公开资料与原文缓存

预测、发言查询、重置状态和信号查询共用核心采集入口。缓存按 `TIBO_STATE_DIR` 共享：CLI、MCP、核心服务和 IM 只要使用同一状态目录，就复用同一份公开资料，不按用户、群聊、语言或命令分别抓取。

## 两层数据

| 层 | 保存位置 | 有效期与用途 |
| --- | --- | --- |
| 原文与历史 | `ledger.json` | 不自动过期，按帖子 ID 合并，保存正文、原帖链接、出处和核实时间 |
| 最新公开资料 | `source-cache.json` | 成功发现帖子后两分钟，复用主页发现结果及同时取得的官方状态、新闻资料 |

最新资料过期后重新检查主页，发现新 ID 后补入历史。已经取得且核实完整的原文不再逐条请求 oEmbed 或单帖页面；主页仍会包含部分旧帖，这是发现新帖所需的列表请求。旧帖不因未出现在最新主页里而删除。

另检查最近 48h、上次 global 之后最多两个未截断的重置相关原帖的官方详情页，补充主页没露出的作者自回复。详情页上的作者、ID、正文和时间均独立校验，之后仍经共享原文核实入口；不执行脚本、不递归爬取回复，不猜测不可读内容。线程发现失败保留现有证据。

原文永久缓存与线程发现用途不同：已知正文不变也不能说明作者后来没有自回复。因此相关详情页在最新资料缓存到期后仍可刷新；两分钟内通过同一事务合并请求，不随查询人数重复读取。`sources` 的 `threads.attempted/discovered` 仅用于本地诊断，不代表完整线程覆盖。

主页若显示同一 ID 的正文有变化，会重新核实；完整原文不会被匹配的截断摘录覆盖。存档或仍截断的正文不能视为完整原文缓存，之后可继续核实、补全。保留原来的核实时间，不把缓存命中标成刚核实。

这里的“永久”指没有自动过期清理，不代表不可修改：管理员确认 `clear-history` 后可以清空；修改或恢复历史也会使短期缓存失效。配置、权限与二次确认保持原规则。

## 并发与失败

同进程请求通过队列协调，跨进程通过状态事务锁协调。第一个请求采集，后续请求等待并读取完成结果；缓存命中不会延长有效期。各请求拿到独立副本，翻译或其他文字处理不会改动共享原文。

主页未能发现帖子时，从失败采集结束起只复用结果 15 秒，减少重复请求并尽快恢复检查。已保存的正文仍可使用，但旧正文和曾经成功的核实不证明本次发现了最新发言。缓存损坏或无法保存时继续正常采集；成功采集过慢且超过两分钟有效期的结果不会保存为可复用缓存。

离线模式不联网、不使用最新资料缓存，也不更新永久历史。指定快照直接读取指定文件。定点报告仍单独生成预测与报告，但可以复用两分钟内已取得的公开资料。

## 与预测缓存的关系

`source-cache.json` 缓存公开输入；`forecast-cache-ai.json` / `forecast-cache-native.json` 缓存两分钟内的预测结果。AI 与非 AI 预测结果分开，但两者和发言查询共用采集缓存。新帖子或公告更新历史后，已有预测缓存提前失效。

使用采集缓存进行新的判断时，等待重置的时钟按当前时间计算，来源的采集时间和帖子的核实时间保留原值。直接复用预测结果时，仍保留那份预测原来的判断时间。这两种命中不要混淆。

逐帖语义提取另有永久 `post-feature-<hash>.json` 缓存：正文、上下文或契约变化才重新提取；有效期和兑现状态每次重算，不缓存成永久“待兑现”。特征模型产物更新也会使预测缓存失效，见 [结构化特征](structured-features.md)。

## 实际检查

```bash
tibo posts --limit 5
tibo forecast --no-ai
tibo diagnose
```

本地诊断的 `collectionReuse.state` 为 `cached` 表示复用了公开资料，`collectedAt` 是原采集时间，`ttlMs` 是有效期，`waitMs` 包含协调等待。`sources[].cached=true`、`fetched=false` 表示来源没有在这次调用重新请求；oEmbed 的 `reused` 为复用原文数量，`attempted` / `verified` 是这次核实数量。普通 posts 不写预测诊断，`diagnose` 仍显示最近保存的预测。

这些细节用于本地排查，不添加到面向用户的简洁预测模板。重装保留两个缓存和已有历史；安装方法见 [安装与运维](operations.md)。
