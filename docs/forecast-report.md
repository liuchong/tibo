# 重置预测报告约定

本文是公开预测报告的实现依据。CLI `forecast`、聊天 `forecast / 预测`、MCP 查询与每天北京时间 09:00 / 21:00 的订阅推送共用此约定。预测数据与报告呈现分开；报告不能修改概率、完成时钟或证据等级。

交互预测在原采集时间之后两分钟内可复用共享结果，同时请求只生成一次；标题及依据沿用该次采集时间，不把缓存命中写成一次新采集。不同接入、预测窗口、语言和后续管道共用判断，展示各自处理。已取得的新证据、经验或相关配置变化会提前失效；北京时间 09:00 / 21:00 的定点报告独立生成。缓存状态与耗时只保存在本地 diagnostics 的 reuse 字段，不增加公开模板字段。

## 固定模板

```markdown
**Codex 重置预测｜北京时间 [MM-DD HH:mm]**

**概率**

• 24h：[X]%
• 48h：[Y]%（含24h）
• 上次重置：[UTC MM-DD HH:mm]，距今 [X.X] 小时

**参考消息**

• [UTC MM-DD HH:mm]｜[发布者：相关消息的一句话摘要]｜[原始来源链接]

**判断理由**

• [支持近期重置或说明仍有机会的主要因素]
• [限制判断或降低预期的主要因素]
```

标题、区块名、顺序与概率字段名固定。参考消息 1–4 条，不凑数；判断理由 1–2 条，每条一句，最多 100 个字符。普通查询标题使用实际采集时刻；定点报告标题使用固定推送时刻，每个定点只生成一次。事件时间统一使用 UTC，距今按采集时刻计算。原有 `horizon=24/48` 单窗口查询仅显示指定概率字段，其余结构一致；默认 both 显示两个字段，48h 包含 24h。

百分比只在有可靠数值依据时填入。已核实官方限时 global 承诺、但兑现历史不足以估计百分比时，包含期限的窗口填“高（已明确预告，暂无可靠百分比）”；期限在窗口外填“暂无法估计（预告期限在窗口外）”。期限已过六小时以内仍缺完成公告时填“待确认（预告期限已过，尚未见完成公告）”。不将尚未结合承诺的普通历史基线作为综合预测输出，也不凭一条预告填写固定的 90%。

报告只给结论、相关证据与权衡原因。不给个人额度周期说明、七天倒计时、算法公式、模型权重、采集数量、搜索/AI 状态、运行环境或额外区块。这些细节保留在 `status`、`stats`、`review`、本地 `--json`、diagnostics 和原理文档中。

## 证据选择

1. Tibo 自己的相关 X 原帖始终优先：最近完成公告、未兑现承诺、相关暗示、仍有效的多日计划及其必要上下文。普通问候、缺少上下文的短回复不占名额。前次重置前的暗示不能再次当作新承诺。
2. 其他原始证据按价值补充：官方尚在影响 Codex 的事故与恢复公告、相关发布，或明确身份来源的直接知情者发言。必须已经取得正文，有准确的原始链接、作者/发布机构和事件时间，且直接涉及 Codex 重置、额度或补偿。搜索摘要、转述与只有获取时间的页面不能充当新事件。
3. 其他人的发言比 Tibo 原帖要求更高：必须核实原帖作者及正文，不能凭 AI 判断作者可信。当前程序只自动获取固定官方账户的相关 X 公告，不自动把陌生账户、匿名消息或截图升级为全局证据。其他直接知情者需要先扩展可核实来源适配器。个人账户变化不能证明 global。
4. 同类预测服务只能提供查证线索，不能提供本程序的概率、评分或统计样本。线索须追溯到真实原文并独立核实；其名称、地址、数值与转述不进入报告、帮助或 AI 证据。重复 URL 和同一事件不重复占名额。

引用必须直接链接原帖或具体公告，不链接搜索结果或预测服务。官方 X 身份通过固定账户和嵌入接口的作者/帖子链接匹配核实；时间由帖子 ID 取得。存档完成正文只作存档证据，摘要不称“官方全文已核实”。发布、事故本身不等于将发生重置，判断理由必须保留这种区别。

## 理由与降级

理由依据选中的证据和当前信号生成，不把闲聊、历史消息或旧承诺拼成新事实。明确日期承诺、条件计划、作者意向、事故与完成公告使用不同措辞。近期刚重置可以说明，但不在既有算法外再减一个固定分数；多日计划仍可作背景，不以旧线索重复调整概率。

官方明确限时 global 承诺出现时，第一句指出承诺和 UTC 期限，不写“没有承诺具体时间”。范围由官方自回复和有效 full reset 计划补齐时，理由说明这种上下文依据。第二句说明可比兑现样本及限制：样本足够可给窗口次数，核实不完整或太少则明确暂无可靠百分比，使用上述定性结论。期限逾期超过六小时后不再维持“高”或待确认覆盖，交回已有算法，并引用逾期未确认的事实。报告不新增区块或公式；置信区间和排除细节保留在本地 `forecast.promisePolicy/promiseHistory`，见 [判断约定](decision-contract.md)。

时间预期与确定承诺使用不同措辞：预计、打算或可能发生重置的原帖，可以作为“重置时间预期”优先引用，并保留其时间词；否定预期不能被日期词翻转成承诺。缺少时区和边界时不显示猜测的 UTC。没有经过验证的时间预期模型时，理由说明该信息尚未支持数值调整，不写“已明显上调”。仍沿用原模板和最多两条理由。

- 没有可用相关消息：参考消息写“未见可用的相关原始消息”。只有旧背景、没有新信号：理由写“本次未见新的明确重置承诺”，不能声称确定不存在。
- 上次完成时刻无法确认：上次重置写“未核实”，不显示确定的距今小时。
- 历史不足：概率字段分别写“暂无法估计”，仍展示可用消息；只有符合审计和样本门槛的承诺历史估计可独立给出数值，单独一条明确期限不生成百分比。
- AI、搜索或辅助来源失败：继续使用自有算法和已取得的证据；不在消息中打印错误和任务状态。只有证据缺失影响结论时，用一句必要的描述性理由说明。
- AI 摘要或补充证据不可核实：舍弃该项，使用本地固定摘要与理由。生成报告本身不增加 AI 请求，也不会随着订阅人数增加采集或模型请求。

## 验收

固定模板覆盖正常、单窗口、近期完成、明确承诺、条件计划、无新信号和历史不足。核对 CLI、聊天、MCP 和定点生成都使用同一渲染；保留 JSON 中的完整模型与采集信息。参考消息不包含未来事件、无日期页面、搜索摘要、无关发言或发现源。真实联网试用与无 AI 试用均应得到完整报告，秘密和本地身份不能进入正文。
