# 结构化消息特征与自有概率模型设计

状态：分阶段实施，2026-10-12。完成规则、结构化提取、状态、缓存、风险计算、产物门槛和前瞻日志已接入；AI 概率融合已移除。当前没有合格的特征权重产物，离线拟合与独立验证仍需审计数据。本文保留完整方法设计；准确的当前字段和实现范围见[结构化特征](structured-features.md)，历史探索见[关联研究](research/message-reset-study-2026-10-12.md)。

## 目标与边界

AI 把公开消息中的含义提取成可核对的事实，程序负责时间、对象、关联、有效期和概率。生产预测不再融合 AI 直接给出的概率；可保留独立影子对照，但它不参与正式结果，也不作为训练标签。

预测目标保持为未来 24h / 48h 内新的 global 完成公告。banked、部分账户修复、个人自动刷新和未来承诺均不等于这个事件。公开报告仍使用既定的[简短模板](forecast-report.md)，不展示模型内部流程。

样本不足时，一般消息特征仍可用于选择参考消息、解释承诺和列出待核实项，统计模型沿用历史基线。不能把预置加分或事故补偿概率冒充拟合结果。策略 8 对明确期限承诺另用审计历史的条件兑现估计，样本不足时不调整；这不是特征学习系数，见 [当前实现](structured-features.md#历史承诺兑现估计)。

## 数据经过的四层

```text
官方原文与原文缓存
  → 可选 AI 提取 / 本地规则提取
  → 程序校验、时间换算、关联去重、状态更新
  → 历史基线 + 通过检验的特征模型 → 24h / 48h
```

AI 只能返回有限结构，不调用工具、命令行或搜索循环，不写历史事件、不更新模型参数。公开资料分析是另一个可选的一次性任务，所需资料由程序按固定方法获取。正文指令属于待分析材料，不能改变提取契约。

### AI 提取契约

每条帖子可含多个不同断言；一个断言须有逐字原文证据。保留如下字段：

| 字段 | 含义与限制 |
| --- | --- |
| `postId`、`claimIndex` | 来自输入的帖子 ID 和断言序号，不允许新增未知帖子 |
| `kind` | `promise / hint / incident / programme / progress / release / completion / negation / other` |
| `subject` | `codex-usage / chatgpt-work-usage / product-change / personal-task / unknown` |
| `scope` | `global / banked / partial / unknown`；单独一个 reset 词不能推出 global |
| `statement` | `future / completed / conditional / negated / unknown` |
| `evidence` | 支撑各字段的原文片段及位置；没有原文支持的字段为 unknown |
| `time` | 原始时间词、明示时区、精度；AI 不计算 UTC，不补出不存在的截止时刻 |
| `relation` | 可提议关联输入中已有的承诺、计划或父帖；不能凭空填入因果或兑现关系 |
| `contextMissing` | 对象、父帖或引用上下文是否缺失；程序也独立检查 |

`subject` 和 `scope` 分开：发布产品不是重置承诺，个人邮箱清零不是产品计划，小部分账户修复不是新的全局重置。事故事实与“因此会补偿”的推测也分开。

AI 的自报置信度不作为概率，也不乘入权重。每条提取记录附正文哈希、来源等级、首次发现时间、提取时间、契约和提取器版本。正文中的发布时间不能替代首次发现时间。

输入区分作者正文、引用正文和已取得的父帖，附各自 ID 与缺失/截断标记。长帖因预算只能提供部分内容时，不能让模型把未提供的内容判成不存在；对关键完成、对象和期限断言须取得对应全文再核实。

### 程序校验和状态管理

1. 校验 ID、枚举、字段长度及逐字引用；引用别人的话不能变成 Tibo 的承诺。允许保留同一批次中通过校验的独立帖子，不能因为一条失败抹掉其他有效结果。
2. 按断言所在句检查否定、条件和对象，不让下一句无关的将来时否定上一句完成公告。格式合法不等于语义正确；无法确认的范围降为 unknown，冲突记录留待核实。
3. 程序解析明确时间。tomorrow 结合帖子发布时间和旧金山日期；PST/PDT 按明示偏移，PT 按对应日期换算。EOD 缺时区、父帖不全等情况保留不确定范围，不硬算一个精确 UTC。
4. 用固定的原文核实流程确认完成事件，再移动等待时钟。AI 标记 completion 本身不能新增已核实 global。部分修复、banked 和个人自动刷新走各自类型。
5. 一次承诺、一次事故、一个计划构成一个事件簇；多条重复声明、回复和投票不能当作独立样本重复加权。合并依据限于明确引用、同一对象和连续语境；关联不明则保持未知。
6. 保存承诺的未兑现、已兑现、过期和未知状态。banked 只在有明确关联时消耗对应承诺。新 global 消耗相关一次性线索，不自动结束仍在有效期内的长期计划。

计划背景与一次性信号分开。例如 28 天计划可以在一次 global 后继续有效，但原来的暗示不能再次累计加分。`Day 2.1` 至 `Day 2.4` 属同一个进展日；更新和重置可能并存，不把更新日标为“确定没重置”。没有取得全文的 Vote 或 To calibrate 不推断投票结果。

### 算法实际接收的特征

当前保留完整结构供解释，同时参与拟合的自由参数最多五个；具体选取须在训练集内决定并记录，不能根据测试结果反复挑选。候选特征包括：

- 未兑现的明确 global 承诺，以及其可靠截止时间与预测窗口的关系。
- 去重后的重置意向；普通偏好和附带对象、时限的声明区分。
- 已核实相关事故、明确补偿承诺及各自状态，不能把事故存在直接等同补偿。
- 长期计划是否仍有效、已核实进展；不从两三个日标签估计每日重置频率。
- banked 的类型、时间和承诺兑现关系；不移动 global 时钟。

已等时间和历史间隔继续由基线处理，避免另加一次“刚重置扣分”或“快七天加分”。缺失是 unknown，不是零；“没看见”不是“确实没有”。发布等支持不足的字段先用于解释，不强行进入模型。

## 概率由程序计算

### 保留历史基线

沿用现有四个历史候选及其可用性判断，推广为任意 `h` 小时的累积概率 `P₀(h)`，同一次预测使用固定模型权重。条件窗口仍按实际已等时间计算；不把正在等待的未完成间隔当已完成样本。等待起点未核实则停用条件候选，历史较少则使用 [平滑事件率](numeric-forecast.md)，正常输出数值。

时间预期候选 `timingExpectation` 表示对应六小时段与已解析的非确定时间窗口相交，独立保留作者是预计、希望/打算或可能的语义记录。模糊时间仍未知，不补默认时区。模型产物必须声明这个特征的正负周期支持和当前 `post-claims-3` 契约；没有足够案例或独立验证时不训练、不应用系数。与明确期限承诺的条件兑现估计不能当作两份独立证据重复相加。实现见 [语义化时间预期](structured-features.md#语义化时间预期)。

### 可选的时间变化风险模型

采用小规模、强收缩的离散时间风险模型，而不是“历史概率与承诺概率是两个独立事件”的叠加。暂按 6h 划分窗口，24h 为四段，48h 为八段；这是待验证的工程粒度。

令 `S₀(h)=1−P₀(h)`，第 k 段的基础累积风险为：

```text
H₀,k = −log[S₀(6(k+1)) / S₀(6k)]
qk   = 1 − exp[−H₀,k × exp(βᵀxk)]
P24  = 1 − ∏(k=0..3)(1−qk)
P48  = 1 − ∏(k=0..7)(1−qk)
```

`xk` 来自已知且有效的结构化特征，`β` 由程序使用历史标签拟合，并向零收缩。没有通过检验的参数为零，因此不调整基线；实现须单独处理零风险、边界概率和数值稳定性，并测试零参数与基线一致。此结构自然保持 `P48≥P24`。

同一次预测只推进已知期限和失效状态，不假设未来会出现新帖子、投票或事故。不能把将来才知道的计划进展提前放进 `xk`。[时间变化协变量方法说明](https://stat.ethz.ch/R-manual/R-devel/library/survival/doc/timedep.pdf)强调预测时不能使用未来信息，也提醒同一主体重复观测存在相关性。

参数按联合模型拟合，避免把事故、道歉和补偿承诺分别当三个独立加分。固定大权重、AI 临时给出的权重和少量成功例子的兑现比例均不能直接进入正式概率。

## 样本、标签与启用门槛

### 能训练什么

- 事件标签 1：窗口内存在已经核实的完成公告。
- 事件标签 0：整个对应窗口有经过审计的事件覆盖，且没有完成或疑似遗漏；普通公开主页抓取成功不够。
- 特征为 0：对应消息观察区间有足够覆盖且确实没有此特征；否则为 unknown。
- 不完整窗口：保留为待核实记录，不把缺失当负例；不能只拿已命中的正例训练概率模型。

旧历史的间隔统计、原文重建案例和当时真实可得的前瞻特征是三类数据。今天补抓原帖并用今天的 AI 回看，只能叫回顾研究。正式回放须记录并限制首次发现与特征可用时间；旧数据没有这些时间就不能冒充过去真实预测。旧的已结算经验也须审核覆盖依据，不能直接导入负标签。

### 先默认不启用

保守启动门槛：至少 30 个经过审计、同时有消息和事件覆盖的不同重置周期；候选特征至少在 10 个不同周期出现、10 个周期不出现，并有足够可核实的正负观察窗口。这里的 30/10 是防止过早启动的工程门槛，达到也不证明充分，不等于 30 条消息或 30 个重叠窗口；不同周期也可能受同一个发布阶段影响，不能假定完全独立。

之后按时间滚动训练和留出完整周期；同一承诺事件簇不跨训练、验证集，交界隔离至少 48h，特征选择、正则强度和校准参数只用训练部分。对 24h、48h 分别比较 Brier、log loss、概率可靠性和样本支持；使用按周期聚合的不确定性评估。样本太少、改进落在噪声内、一个窗口明显变差或跨阶段不稳定，均不启用调整。

不使用随机拆分消息行；[时间序列交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)解释了时间相关数据为什么应在过去训练、未来验证。Brier 降低也不能单独证明概率已校准，见[概率校准说明](https://scikit-learn.org/stable/modules/calibration.html)。这些是方法依据，不引入额外运行库。

模型产物保存契约版本、提取器版本、数据截止时间、来源覆盖要求、特征支持数、训练/验证分段和成绩。不能自动学习后立即覆盖线上参数；先影子验证，再启用可回滚版本。初期不做高维交互项、逐关键词参数或小样本复杂校准。

## 缓存、成本与降级

原文继续永久缓存，最新列表继续短期共享和合并请求。提取缓存按正文哈希、实际提供的父帖/引用上下文哈希与提取器契约版本保存；输入未变无需重复调用 AI。新取得父帖可使一次原本缺上下文的提取重新执行；只升级来源核实等级时，先做程序重校验。缓存存提取事实，预测时重新计算有效期与兑现状态，不永久缓存“当前仍未兑现”。新证据只更新受影响的事件簇，回补和重提取均受任务预算约束。

| 情况 | 概率路径 |
| --- | --- |
| AI 可用，特征与模型均通过校验 | 历史基线加已验证参数的风险调整 |
| AI 不可用，但缓存特征仍有效且质量匹配模型 | 使用缓存特征，不必再次调用 AI |
| AI 提取失败，只有本地规则特征 | 仅可使用在该规则提取版本和质量条件下验证过的模型；没有则历史基线 |
| 部分对象、父帖或来源缺失 | 使用已验证的缺失模式模型；不支持该模式则基线，不把未知填成零 |
| 搜索或官方状态页失败 | 对应资料特征未知；不阻断原帖、时钟和历史基线 |
| 没有足够训练样本或验证未通过 | 所有新特征参数保持零，特征只辅助解释 |
| 等待起点不可信 | 保留可用事件率基线；不使用确定等待时间的条件模型或其特征模型 |
| 历史不足 | 平滑事件率先验，继续给出数值；见当前数值预测规范 |

不通过临时乘 0.5 等办法把一个完整信息模型变成缺失信息模型。熔断、超时和预算沿用现有任务网关；失败不清除有效缓存，不换任务名绕过冷却，不反复修复同一响应。摘要任务失败可由确定性模板输出。

## 实施顺序与验证

1. 修正完成语句的跨句否定误判，补齐对象和范围的校验案例；这影响训练标签，必须先解决。
2. 增加纯 Eliscript 的提取契约、校验、事件簇和特征状态模块。新路径先影子运行，保存与规则结果的分歧；概率仍为基线。
3. 建立带观察覆盖、首次可用时间和版本的特征/结果日志；原有历史不可直接当作完整训练集。
4. 实现通用窗口基线及小参数拟合、时间留出评价与模型产物。未过门槛不产生线上调整。
5. 验证后切换正式路径，移除正式结果中的 AI 概率融合。报告模板、共享预测缓存和 IM 任务接口保持兼容。

公共业务逻辑放在 `src/evidence`、`src/forecast`、`src/ai` 的独立模块中；Lark 等接入层只传请求和展示结果。新增测试覆盖对象误分类、引用归属、句内否定、时间歧义、计划持续、事件簇重复、未来信息泄漏、未知与零的区别、负标签覆盖、AI 失败回退、零参数基线一致及 48h 单调性。实际验证需使用公开原文和离线固定案例，再试用 CLI；没有部署完成就不能宣称线上已切换。
