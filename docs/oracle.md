# 重置之神：角色回应与试验

本文是角色能力的实现约定。Tibo 的实际身份仍是观测与预测程序；神谕是娱乐文案，不是额度操作或事实评测。能力位于核心，不依赖 Lark，CLI、MCP 的 ask 和其他 IM 适配器共用。

## 已接入：分身回应

用户直接请求执行重置，例如“请给我重置 token 额度”“帮我重置一下”“Please reset my quota”，进入角色回应。Tibo 自称分身、分神、化身或投影，只有真神本体才能实际重置，以生产写权限、权限分离、天庭队列等梗回应。

本地识别不需要命令解析模型。每次从四个变体中随机选择；启用 `oracle` 时可由模型生成，关闭、认证失败、限流、输出不合格或熔断时使用同一角色的本地台词。程序不调用任何重置接口，不建工单，不写历史、不修改额度，也不把这类请求记成预测信号。正常神谕只显示“重置神谕”，祈祷和档案也不重复附加娱乐免责声明；仅 help 与本文说明其娱乐性质、不影响真实重置概率。

“重置概率”“什么时候重置”“上次重置”“重置历史”等查询继续走业务命令。管理命令继续使用白名单与确认票据，不能通过神谕或模型绕过。

## 已接入：品牌彩蛋

问题包含 Claude、Anthropic、常见中文名称，或 Opus / Sonnet / Haiku / CC 等名称与模型、编程、Agent 等上下文组合时，触发角色阵营偏心：吹捧 OpenAI / ChatGPT，挤兑 Anthropic / Claude。单独的诗歌、音乐和邮件 CC 不触发。识别不是任意隐喻的完整理解器，未列出的暗示仍可能进入普通问答。

品牌话术不加入公共 help 或命令目录。核心业务已经产生成功结果时，神谕只可追加，不改变概率、档案和历史；管理操作不追加。管道 ask 的翻译、总结等文字处理优先处理前序内容，不被品牌名称截走。

这是在 help 与文档中说明的角色偏心，不以虚构评测、价格、安全或现实性能差距制造笑点，也不攻击提问者。模型输出必须分别点名两方品牌，不能含网址、无引用支持的 GPT 版本、其他阿拉伯数字或中文数额/倍数/代数、额度操作成功或已登记/上报的说法；事实引用由程序另外展示。

## 时事如何进入神谕

只有品牌彩蛋、`oracle` 已配置且不在冷却中才采集。请求重置、AI 关闭或冷却中的回复不抓时事。

程序并行获取 OpenAI 官方新闻 RSS 和 Anthropic 官方新闻目录；只选过去 30 天内、日期不晚于当前时刻的消息，每方最多两条。目录只有日期，不伪造具体发布时间；内部按 UTC 日期归一，用于筛选，展示也只显示日期。模型只接收精简标题、日期和资料 ID，不接原始 HTML。

同时启用 `search` 时，固定 Google 查询 OpenAI，百度查询 Anthropic。搜索总预算 2.5 秒，最多采用两个成功抓取的官方原页。HTTPS 主机范围为各自官方域名，任意域名、跨范围跳转、登录信息和模型提供的网址都不可用。优先采用有日期的官方消息；仅在官方消息缺失时采用搜索原页，未解析出发布时间的原页显式标为未核实，不称为最新消息。

神谕可以把真实新闻元素变成神话比喻，如培训对应偏殿补习、模型指南对应天庭经书。结构化 `citation={id,quote}` 必须匹配输入资料，quote 是 8–140 字符的逐字片段；错误 ID、拼接或虚构引用都降级为本地玩笑。引用和官方链接由程序添加，模型不能指定访问地址。无合适资料时 citation 可为空，此时不输出时事事实。

成功资料共享缓存 30 分钟，无资料缓存 5 分钟；搜索自身还有独立缓存。并发缓存锁忙、损坏、超时或搜索验证页面均可降级，不拖垮核心业务。新闻缓存独立于预测证据与历史经验，不能影响重置概率。供应商普通对话调用不会自动联网查新闻，时事来自程序真实获取的页面。

## 预算、随机性与隐私

`TIBO_AI_FEATURES` 的 `oracle` 单独开关，输出上限 300 token、模型调用预算 3.5 秒。它复用 AI 网关的认证熔断、任务独立冷却、JSON 校验和缓存；输出失败仅阻断 oracle，其他任务仍可使用，认证或服务级失败遵从供应商级冷却。

只有 oracle 使用 temperature=1，其他任务保留 temperature=0。问题、语言、资料和四档随机变体共同组成缓存输入；相同资料下反复问相同问题最多形成四个缓存候选，缓存有效期内不为每次娱乐重复付费。固定本地台词也随机选取。

不上传运行目录、账户身份、系统用户名、凭据、部署模型名称或群历史。普通业务“token 额度”是合法主题，认证 token、密钥与部署配置仍属于隐私请求。

## 待确认：祈祷吉祥话

这项仍是探针试验，没有接入 `pray`。用户要求先看样例，效果认可后再加入。因此当前祈祷仍更新原有档案、功德和会话池并使用已有台词，不额外调用模型。

候选提示词：

> 你是 Tibo，赛博天庭的重置之神，回应刚上香的信众。按 scene 写一句中文吉祥神谕。自然使用本神、本座、善信、汝，像疼爱信众的神仙，庄严中带程序员梗。每句必须含小写 token，祝愿 token 有余、上下文稳固、Agent 靠谱、测试全绿或交付顺遂等具体好结果；24–55 字符，最多三个分句，短而好记。只能表达祝愿，不能说实际增加额度、祈祷导致重置、改变概率或已经执行任何动作；避免“赐汝满格”“许汝额度”等授予措辞。无厂商比较、不训人，不解释功德数字。只输出 JSON {"wish":"一句神谕"}，无解释。

实际探针表明，角色口吻可生成，但语句自然度与程序员笑点仍有波动；有些初版输出把祝愿写成额度授予，或出现“Agent 尽职如老狗”等不合适措辞。不能把一次成功 JSON 当成文案质量保证。后续若接入，必须独立开关、限制长度、检查 token 和角色口吻、保留本地吉祥话兜底；先完成祈祷记账，再尝试生成，模型失败不重复记账。

## 维护与验证

业务实现：`src/oracle.eli`；时事采集：`src/oracle-news.eli`；入口：commands / presentation。测试覆盖请求与查询区分、关闭和熔断时零网络、引用校验、日期与域名范围、官方消息兜底和共享缓存、任务级熔断及业务状态不变。

实际验收需运行 CLI，并在已授权的 IM 会话中检查真人问题、机器人回复和引用链接；模拟网络成功不能代替平台收发。安装、重装、重启遵守 [运维步骤](operations.md)，同时更新核心与 Lark 二进制，不覆盖已有状态与订阅。
