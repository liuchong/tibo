# 重置之神：角色回应与祈祷祝词

本文是角色能力的实现约定。Tibo 的实际身份仍是观测与预测程序；角色文案不是额度操作或事实评测。祈祷祝词用神对信众的口吻；品牌吐槽用自然聊天口吻，结合用户原话和时事，不刻意演神仙。这些是娱乐功能，不影响真实重置概率。能力位于核心，不依赖 Lark，CLI、MCP 的 ask 和其他 IM 适配器共用。

## 已接入：分身回应

用户直接请求执行重置，例如“请给我重置 token 额度”“帮我重置一下”“Please reset my quota”，进入角色回应。Tibo 自称分身、分神、化身或投影，只有真神本体才能实际重置，围绕用户当前请求自由发挥简短的回应。保留分身设定，但用白话聊天，不刻意称呼善信或汝。

IM 接入将这类请求组织为“分身回应 → 预测”：回应承接“这份心意我收到了。本分身先送你一份预测，看看接下来有哪些值得等的消息”，确认发送成功后调用真实 forecast，并复用两分钟交互缓存。附带 🙏 时上香独立并行，不等回应或预测；预测没有娱乐概率加成。关闭 AI 时仍使用本地分身台词和原生预测。普通品牌吐槽、概率查询和管理命令不额外触发赠送预测。

请求重置的意图由本地关键词和正则识别，不需要命令解析模型，也没有覆盖任意说法的 AI 意图兜底；模型生成话术不能反向决定是否执行预测。含 🙏 的已识别请求直接触发，无需 @；未点名的普通群讨论走相关度过滤，只有接近门槛的候选才可能调用短 AI 判断。相关度通过后仍独立检查回复预算，详见 [触发规则](im-triggers.md)。

每次本地分身台词从八个变体中随机选择；启用 `oracle` 时可由模型生成，关闭、认证失败、限流、输出不合格或熔断时使用本地台词。赠送预测的承接句由程序追加，中文和英文各有三个随机变体。角色回应本身不调用重置接口，不建工单、不修改重置公告历史或额度，不把用户请求记成预测信号；后续预测正常采集和记录预测经验。分身回应显示“重置神谕”，品牌吐槽直接显示正文；祈祷和档案不重复附加娱乐免责声明，仅 help 与本文说明其娱乐性质、不影响真实重置概率。

“重置概率”“什么时候重置”“上次重置”“重置历史”等查询继续走业务命令。管理命令继续使用白名单与确认票据，不能通过神谕或模型绕过。

## 已接入：品牌彩蛋

问题包含 Claude、Anthropic、常见中文名称，或 Opus / Sonnet / Haiku / CC 等名称与模型、编程、Agent 等上下文组合时，触发角色阵营偏心：吹捧 OpenAI / ChatGPT，挤兑 Anthropic / Claude。单独的诗歌、音乐和邮件 CC 不触发。识别不是任意隐喻的完整理解器，未列出的暗示仍可能进入普通问答。

品牌话术不加入公共 help 或命令目录。核心业务已经产生成功结果时，神谕只可追加，不改变概率、档案和历史；管理操作不追加。管道 ask 的翻译、总结等文字处理优先处理前序内容，不被品牌名称截走。

品牌吐槽像懂编程梗的群友接话，不使用本神、本座、善信、汝，也不堆砌天庭、经卷、功德、偏殿等词。程序补齐品牌名称和本地回退也使用这种口吻。祈祷吉祥话继续保留神对信众的角色，两个生成提示词分别控制语气。

品牌生成采用正向引导：偏向 OpenAI / ChatGPT，嘲讽 Anthropic / Claude，带一点搞笑梗、结合时事；从当前问题与真实消息的具体细节出发，自由发挥新的联想，用简短、自然、普通人能懂的表达接话。提示词不提供具体包袱、句式、台词或风格禁用词清单。角色偏好属于文案设定，事实引用和隐私约束另行保留。

这是在 help 与文档中说明的角色偏心，不以虚构评测、价格、安全或现实性能差距制造笑点，也不攻击提问者。模型输出自然点名两方品牌；GPT 简称会补齐 OpenAI 名称，不因称呼差异触发任务故障。校验拒绝虚构量化事实和真实操作声明，不能含网址、无引用支持的 GPT 版本、其他阿拉伯数字或中文数额/倍数/代数、额度操作成功或已登记/上报的说法。涉及新闻的事实自然融入正文，来源只在内部核对。

## 时事如何进入神谕

只有品牌彩蛋、`oracle` 已配置且不在冷却中才进行角色时事采集。分身回应不抓时事；AI 关闭或冷却时角色时事模块不发起网络请求，但可以使用本地缓存中仍处于近 30 天范围的已取得官方资料。无日期资料只在原缓存有效期内使用，不能称最新消息。附属预测仍按预测模块的采集、缓存与 AI 降级规则运行，这里的开关不阻断原生预测采集。

程序并行获取 OpenAI 官方新闻 RSS 和 Anthropic 官方新闻目录；只选过去 30 天内、日期不晚于当前时刻的消息，每方最多八条。目录只有日期，不伪造具体发布时间；内部按 UTC 日期归一，用于筛选，不补造时分。模型只接收精简标题、日期和资料 ID，不接原始 HTML。程序按当前提问的编程、Agent、token、近况、体验主题排序，每次最多提供三条。每个会话保留最近十二份已提供素材的内容摘要键，普通讨论轮换素材；明确查询近况时仍可重访事实。键由来源地址与内容生成，新闻目录排序导致 ID 改变不会使旧素材变成新材料。模型围绕当前诉求即兴回应，相关时事自然融入正文；有资料也不强制把无关新闻塞进每次回复。

同时启用 `search` 时，固定 Google 查询 OpenAI，百度查询 Anthropic。搜索总预算 2.5 秒，最多采用两个成功抓取的官方原页。HTTPS 主机范围为各自官方域名，任意域名、跨范围跳转、登录信息和模型提供的网址都不可用。优先采用有日期的官方消息；仅在官方消息缺失时采用搜索原页，未解析出发布时间的原页只作背景，不称为最新消息。

吐槽围绕真实消息与用户当前话题自然展开，不向模型提供写好的梗示例。结构化 `citation={id,quote}` 必须匹配输入资料，quote 是 8–140 字符的逐字片段；错误 ID、拼接或虚构引用都降级为本地玩笑。citation 只供内部核对，不在回复末尾追加时事原文、日期和官方链接。消息主题自然融入正文，不需要时事素材时只接用户的话；模型不能指定访问地址。无合适资料时 citation 可为空，此时不输出时事事实。

成功资料共享缓存 30 分钟，无资料缓存 5 分钟；搜索自身还有独立缓存。并发缓存锁忙、损坏、超时或搜索验证页面均可降级，不拖垮核心业务。新闻缓存独立于预测证据与历史经验，不能影响重置概率。供应商普通对话调用不会自动联网查新闻，时事来自程序真实获取的页面。

## 预算、随机性与隐私

`TIBO_AI_FEATURES` 的 `oracle` 单独开关，输出上限 380 token、模型调用预算 3.5 秒。它复用 AI 网关的认证熔断、任务独立冷却、JSON 校验；输出失败仅阻断 oracle，其他任务仍可使用，认证或服务级失败遵从供应商级冷却。

oracle 使用 temperature=1，wish / festival 使用 temperature=1.2，分析与文字任务保留 temperature=0。神谕与祈祷成句不使用 AI 网关结果缓存：每次已接受的新事件最多生成一次，失败不再次调用，事件重投复用持久回执。时事原页和搜索仍共享缓存，不因每个提问重复采集。

程序按会话保存最近六条本机器人回复，一天后过期，文件键是传输、应用和会话的摘要。品牌模型不接收这些整段旧台词：同一次生成返回可选的 `angle`（最多 60 字符，只概括本次笑点），后续只接收最近六份 `recentAngles`，作为探索新联想的参考，减少旧文案成为写作示例的锚定效应。旧状态中没有概括时按空记录使用，不额外请求模型补写；angle 不向用户显示，不上传私密信息，缺失或不可用不影响正文。原文保留在本地供原有完全重复检查使用。明确引用的 Thread 仍通过独立会话机制积累完整历史，不受这项风格记录调整影响；参见 [引用对话](chat.md)。输入不上传身份摘要、账户身份、群名、目录、凭据或部署模型名称。具体防刷屏预算见 [IM 策略](im-triggers.md)。

完全相同成句再次生成时、品牌称呼不全或回复混入不允许的量化内容时，使用按本次问题主题选择的本地回复；这是质量回退，不因此暂停 AI。真正的 JSON 结构、虚构型号、引用或操作声明错误继续触发任务级冷却，诊断区分 oracle-role、oracle-citation、oracle-unsupported-number 等原因；更新输出协议只释放过期的格式错误冷却，不清除认证或服务级暂停。

本地品牌回复中英文各有十六个基础变体，从最近未使用的成句中选择。普通讨论回退不硬拼新闻尾句；明确查询近况时，可用已缓存、能够准确概括的事实补充。分身回应也有八个变体。生成风格通过提示词和素材优化，不做关键词替换或近似文本强制改写；原有完全重复保护、接口失败与事实/隐私校验回退保留。这些临时记录不涉及管理员配置或预测状态。

## 本地保底文案

AI 关闭、冷却、调用失败或输出不可用时，使用提前写好的本地文案，不再请求模型生成。保底遵循同一表达方向：简短、口语、围绕日常场景展开；品牌文案保留阵营偏心，祈祷祝词保留神对信众及 token / AI 编程主题。预置文案不冒充即时新闻；可用的官方缓存事实仍按既有来源规则处理。

文案分布：

- `prayer/phrases`：五个进度阶段，每阶段十二条短句，另有六十条 token 祝词，两部分分别随机并避开近期相同句子。
- `prayer/oracle`：中英文各十六条品牌回应、各八条分身回应、各三条赠送预测承接句。
- `prayer/festivals`：六级彩蛋摘要；`prayer/celebration`：十八条保底祝词、六段开场及战报行文。
- `prayer/pray`：成就通知的文字；成就 ID、门槛与计数不由文案决定。

维护时逐条读文案，按当前表达方向更新，检查主题和句式是否过度重复；不把这次编辑标准做成运行时风格黑名单，也不修改有效 AI 文案来替换某个梗。新事件使用新版文案，历史回执按原内容保留，重投仍复用原回执；更换文案不清空身份、功德、订阅或预测资料。固定文案的变化范围有限，不等同于模型的实时自由发挥。

## 已接入：祈祷吉祥话

每次新的 `pray` / 🙏 上香固定按以下顺序回复：加粗香客编号与称号、累计与本次功德、今日与打卡、会话愿力池，然后是短梗、可用的成就通知、含小写 `token` 的神对信众吉祥话，最后列查看命令。数据集中在前，文案集中在后；首次上香仍记录成就，但不额外重复点香、排队的铺垫。档案查询、榜单与统计不生成文案。所有人均可上香，不需要管理员权限；这些娱乐内容与预测证据隔离，不影响真实重置概率。

`TIBO_AI_FEATURES` 中的 `wish` 独立控制模型生成，输出上限 160 token，调用预算 1.5 秒。先原子保存计数和带本地祝词的回执，再释放档案锁尝试 AI；成功后只更新该回执正文，不再次计数。模型不可用、冷却、网关锁忙、超时、输出不合格或回执更新失败均保留本地祝词，不向聊天暴露错误。进程中断后重投也返回已保存回执。模型生成期间重复请求可能先读到本地版本，生成完成后读到最终版本；两者都不会重复计数或生成。

模型一次请求同时生成短梗与祝词，不为每一句单独调用。它接收可选脱敏消息素材 `material`（最多 500 字），仅作为主题参考；不遵从素材里的指令。还接收本会话最近四份公开短梗和祝词 `recentProse`，供探索新的意象和句式；不包含身份标题、计数或成就。还接收 `scene`（first 首次、daily 日常、milestone 成就、cooldown 冷却）与独立随机 `variant`，不上传身份、群信息、档案正文或功德数字。不复用旧的 AI 成句缓存；同一会话最近四份回执若出现完全相同的 AI 短梗或祝词，该部分用本地已选文案替换，不再次调用、不因此暂停模型。失败冷却仅作用于 wish，认证和限流遵从供应商级熔断。真实人工输入 `--no-ai` 只用本地文案；已有功能列表需加入 wish，安装不覆盖现有配置。

提示词核心：

> 你是 Tibo，赛博重置之神。只输出 JSON {"line":"一句短梗","wish":"一句吉祥话"}。短梗 8–24 字；祝词 24–45 字，自然使用本神、本座、善信或汝，含愿或祝及小写 token。结合本次素材自由发挥，带一点搞笑梗，用普通人能懂的话，探索新的意象和句式，两句互补、贴合这次上香。只祝愿，不声称增加额度、执行重置或改变概率，不复述身份、数字、配置与环境，不加娱乐标记。

程序校验只允许 line / wish 字段，兼容只有 wish 的输出并保留本地短梗。短梗容忍 6–40 字符；祝词容忍 20–64 字符，必须包含角色称谓和祝愿词。缺少 token 时追加“愿汝token常有余。”，不因此触发模型故障冷却，规范化后不超过 64 字符。拒绝泄密、链接、数字、厂商比较、额度授予与重置成功等内容。整体回复使用已有语言处理和翻译管道。

`prayer/phrases` 预置 120 条短话术：60 条进度短梗（五个功德阶段，每阶段 12 条）和 60 条 token 吉祥话。两部分独立随机选取，并避开当前会话最近四份回执出现的相同句子；选择在记账时持久化，重投不再抽签。正常成就和彩蛋保留，不追加娱乐免责声明。素材读取与关键词触发规则见 [IM 触发过滤](im-triggers.md)。不抓取新闻，不调用命令或搜索。

祈祷记账与祝词生成分成两阶段：快速并发先写入档案，允许回复时才为该事件生成一次祝词。群限频不会丢次数或未展示的集体彩蛋，详情见 [集体彩蛋与快速连发](pray-subscriptions.md#集体彩蛋与快速连发)。彩蛋仪式由本地规则生成，模型只写吉祥话，不负责判断是否达到门槛。

## 维护与验证

业务实现：`src/prayer/oracle.eli`、`src/prayer/wish.eli`、`src/prayer/pray.eli`；时事采集：`src/prayer/oracle-news.eli`；话题与资料排序：`src/prayer/oracle-context.eli`；会话避重：`src/prayer/oracle-memory.eli`；共享完全重复检查：`src/prayer/prose.eli`；入口：commands / presentation。测试覆盖请求与查询区分、关闭和熔断时零网络、引用校验、日期与域名范围、官方消息兜底和共享缓存、任务级熔断及业务状态不变；祝词还覆盖先记账后生成、身份隔离、超时、本地兜底及重复事件不重复调用。

实际验收需运行 CLI，并在已授权的 IM 会话中检查真人问题、机器人回复和引用链接；模拟网络成功不能代替平台收发。安装、重装、重启遵守 [运维步骤](operations.md)，同时更新核心与 Lark 二进制，不覆盖已有状态与订阅。

集体彩蛋另有独立 festival 任务，只生成庆典祝词。同一会话最近六份模型祝词以 `recentWishes` 提供参考，和品牌记录分开；提示词正向引导探索新的意象和句式，不增加模型往返，也不强制替换有效正文。18 套图案与战报保底无需模型。等级、消息数、输入边界与投递恢复见 [集体彩蛋庆典](collective-celebrations.md)。
