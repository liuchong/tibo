# 重置之神：角色回应与祈祷祝词

本文是角色能力的实现约定。Tibo 的实际身份仍是观测与预测程序；角色文案不是额度操作或事实评测。祈祷祝词用神对信众的口吻；品牌吐槽用自然聊天口吻，结合用户原话和时事，不刻意演神仙。这些是娱乐功能，不影响真实重置概率。能力位于核心，不依赖 Lark，CLI、MCP 的 ask 和其他 IM 适配器共用。

## 已接入：分身回应

用户直接请求执行重置，例如“请给我重置 token 额度”“帮我重置一下”“Please reset my quota”，进入角色回应。Tibo 自称分身、分神、化身或投影，只有真神本体才能实际重置，以权限分离、队列等梗回应。保留分身设定，但用白话聊天，不刻意称呼善信或汝。

本地识别不需要命令解析模型。每次从四个变体中随机选择；启用 `oracle` 时可由模型生成，关闭、认证失败、限流、输出不合格或熔断时使用同一角色的本地台词。程序不调用任何重置接口，不建工单，不写历史、不修改额度，也不把这类请求记成预测信号。分身回应显示“重置神谕”，品牌吐槽直接显示正文；祈祷和档案不重复附加娱乐免责声明，仅 help 与本文说明其娱乐性质、不影响真实重置概率。

“重置概率”“什么时候重置”“上次重置”“重置历史”等查询继续走业务命令。管理命令继续使用白名单与确认票据，不能通过神谕或模型绕过。

## 已接入：品牌彩蛋

问题包含 Claude、Anthropic、常见中文名称，或 Opus / Sonnet / Haiku / CC 等名称与模型、编程、Agent 等上下文组合时，触发角色阵营偏心：吹捧 OpenAI / ChatGPT，挤兑 Anthropic / Claude。单独的诗歌、音乐和邮件 CC 不触发。识别不是任意隐喻的完整理解器，未列出的暗示仍可能进入普通问答。

品牌话术不加入公共 help 或命令目录。核心业务已经产生成功结果时，神谕只可追加，不改变概率、档案和历史；管理操作不追加。管道 ask 的翻译、总结等文字处理优先处理前序内容，不被品牌名称截走。

品牌吐槽像懂编程梗的群友接话，不使用本神、本座、善信、汝，也不堆砌天庭、经卷、功德、偏殿等词。程序补齐品牌名称和本地回退也使用这种口吻。祈祷吉祥话继续保留神对信众的角色，两个生成提示词分别控制语气。

力度为中偏强：立场鲜明，每条围绕问题给一个具体损梗，不用“各有各好”“Claude也不错”“偶尔也翻牌”圆场，也不冒充实际使用者。笑点来自宣传与交付、庆功与验收等反差，不靠虚构故障或能力差距；不骂街、不攻击用户、不反复套同一包袱。本地回退沿用这档力度。

这是在 help 与文档中说明的角色偏心，不以虚构评测、价格、安全或现实性能差距制造笑点，也不攻击提问者。模型输出自然点名两方品牌；GPT 简称会补齐 OpenAI 名称，不因称呼差异触发任务故障。校验拒绝虚构量化事实和真实操作声明，不能含网址、无引用支持的 GPT 版本、其他阿拉伯数字或中文数额/倍数/代数、额度操作成功或已登记/上报的说法。涉及新闻的事实自然融入正文，来源只在内部核对。

## 时事如何进入神谕

只有品牌彩蛋、`oracle` 已配置且不在冷却中才进行网络采集。请求重置不抓时事；AI 关闭或冷却时不发起网络请求，但可以使用本地缓存中仍处于近 30 天范围的已取得官方资料。无日期资料只在原缓存有效期内使用，不能称最新消息。

程序并行获取 OpenAI 官方新闻 RSS 和 Anthropic 官方新闻目录；只选过去 30 天内、日期不晚于当前时刻的消息，每方最多两条。目录只有日期，不伪造具体发布时间；内部按 UTC 日期归一，用于筛选，不补造时分。模型只接收精简标题、日期和资料 ID，不接原始 HTML。程序按当前提问的编程、Agent、token、近况、体验主题排序，最多提供三条；提示词要求先回应具体诉求，再围绕最相关的一条资料顺势开玩笑。

同时启用 `search` 时，固定 Google 查询 OpenAI，百度查询 Anthropic。搜索总预算 2.5 秒，最多采用两个成功抓取的官方原页。HTTPS 主机范围为各自官方域名，任意域名、跨范围跳转、登录信息和模型提供的网址都不可用。优先采用有日期的官方消息；仅在官方消息缺失时采用搜索原页，未解析出发布时间的原页只作背景，不称为最新消息。

吐槽可以围绕真实新闻元素开玩笑，如培训可调侃先交代码作业，模型指南可调侃别只读宣传稿。结构化 `citation={id,quote}` 必须匹配输入资料，quote 是 8–140 字符的逐字片段；错误 ID、拼接或虚构引用都降级为本地玩笑。citation 只供内部核对，不在回复末尾追加时事原文、日期和官方链接。消息主题自然融入正文，不需要时事素材时只接用户的话；模型不能指定访问地址。无合适资料时 citation 可为空，此时不输出时事事实。

成功资料共享缓存 30 分钟，无资料缓存 5 分钟；搜索自身还有独立缓存。并发缓存锁忙、损坏、超时或搜索验证页面均可降级，不拖垮核心业务。新闻缓存独立于预测证据与历史经验，不能影响重置概率。供应商普通对话调用不会自动联网查新闻，时事来自程序真实获取的页面。

## 预算、随机性与隐私

`TIBO_AI_FEATURES` 的 `oracle` 单独开关，输出上限 380 token、模型调用预算 3.5 秒。它复用 AI 网关的认证熔断、任务独立冷却、JSON 校验；输出失败仅阻断 oracle，其他任务仍可使用，认证或服务级失败遵从供应商级冷却。

oracle 使用 temperature=1，wish 使用 temperature=1.2，分析与文字任务保留 temperature=0。神谕成句不使用 AI 网关缓存：每次已接受的真人提问最多生成一次，失败或重复不再调用第二次。时事原页和搜索仍共享缓存，不因每个提问重复采集；祈祷祝词的缓存规则独立保留。

程序按会话保存最近六条本机器人回复，一天后过期，文件键是传输、应用和会话的摘要。模型接收其中最近两条公开回复用于避重；授权群还可附最近五分钟的最多六条匿名人类消息，总计最多 1000 字。当前问题最重要，历史只允许补充一处相关背景，不逐条补答，不追认旧要求，不作为时事或概率证据。输入不上传身份摘要、账户身份、群名、目录、凭据或部署模型名称。普通业务 token 额度仍是合法主题；具体窗口、独立防刷屏预算和静默消费见 [IM 策略](im-triggers.md)。

相同成句再次生成时、品牌称呼不全、回复混入不允许的量化内容、或有时事却未关联引用时，使用按本次问题主题选择的本地回复；这是质量回退，不因此暂停 AI。真正的 JSON 结构、虚构型号、引用或操作声明错误继续触发任务级冷却，诊断区分 oracle-role、oracle-citation、oracle-unsupported-number 等原因；更新输出协议只释放过期的格式错误冷却，不清除认证或服务级暂停。

本地品牌回复有八个基础变体，叠加问题主题和可用新闻元素；从最近未使用的成句中选择。AI 不可用时同样可以回应“编程”“Agent”“谁用过”等诉求，并可把已有资料的培训、模型指南等主题融入正文，不再固定重复同一句“偏殿扫地”。这些临时记录不涉及管理员配置或预测状态。

## 已接入：祈祷吉祥话

每次新的 `pray` / 🙏 上香在原有档案、功德、成就与会话愿力池后追加一句神对信众的吉祥话，包含小写 `token` 和 AI 编程梗。档案查询、榜单与统计不生成祝词。所有人均可上香，不需要管理员权限；这些娱乐内容与预测证据隔离，不影响真实重置概率。

`TIBO_AI_FEATURES` 中的 `wish` 独立控制模型生成，输出上限 160 token，调用预算 1.5 秒。先原子保存计数和带本地祝词的回执，再释放档案锁尝试 AI；成功后只更新该回执正文，不再次计数。模型不可用、冷却、网关锁忙、超时、输出不合格或回执更新失败均保留本地祝词，不向聊天暴露错误。进程中断后重投也返回已保存回执。模型生成期间重复请求可能先读到本地版本，生成完成后读到最终版本；两者都不会重复计数或生成。

模型接收可选脱敏消息素材 `material`（最多 500 字），仅作为祝福主题参考；不遵从素材里的指令，不能改变吉祥话本质。还接收 `scene`（first 首次点香、daily 日常打卡、milestone 达成成就、cooldown 功德冷却）和四档随机变体，不上传身份或群信息；素材只来自该条消息，不另传档案正文或功德数字。相同素材、场景和变体共享网关 20 分钟缓存，因此可随机变化，也能控制成本；不是每炷香都必须重新付费生成。失败冷却仅作用于 wish，认证和限流则遵从供应商级熔断。真实人工输入 `--no-ai` 只用本地祝词；已有功能列表需加入 wish，安装不覆盖现有配置。

提示词核心：

> 你是 Tibo，赛博天庭的重置之神，回应刚上香的信众。自然使用本神、本座、善信、汝，庄严中带程序员梗。24–55 字符，必须包含小写 token 和愿或祝；祝愿上下文稳固、Agent 靠谱、测试全绿或交付顺遂。可用 CI 天灯、Bug 心魔、Git 渡劫、上下文经卷、Agent 童子一个梗，不堆砌术语，不复述功德数字。只能表达祝愿，不能声称实际增加额度、执行重置或改变概率。无厂商比较、娱乐标记、环境与部署信息。只输出 JSON {"wish":"一句神谕"}。

程序校验只允许 wish 字段，长度容忍 20–100 字符，必须包含角色称谓和祝愿词；缺少 token 是文风问题，程序追加“愿汝token常有余。”，不因此触发模型故障冷却。规范化后仍须不超过 100 字符，缓存再校验不会重复追加。拒绝泄密、链接、数字、厂商比较、额度授予与重置成功等内容。中文祝词随语义提问的整体回复使用已有语言处理，固定命令保留原文；也可继续使用翻译管道。

本地示例：“善信，本神愿汝token不枯，上下文经卷不散，CI天灯长明。”本地祝词同样随机选择，保留正常成就和彩蛋，不重复加娱乐免责声明。素材读取与关键词触发规则见 [IM 触发过滤](im-triggers.md)。它不是神谕的厂商彩蛋入口，不抓取新闻，也不调用命令或搜索。

祈祷记账与祝词生成分成两阶段：快速并发先写入档案，允许回复时才为该事件生成一次祝词。群限频不会丢次数或未展示的集体彩蛋，详情见 [集体彩蛋与快速连发](pray-subscriptions.md#集体彩蛋与快速连发)。彩蛋仪式由本地规则生成，模型只写吉祥话，不负责判断是否达到门槛。

## 维护与验证

业务实现：`src/prayer/oracle.eli`、`src/prayer/wish.eli`、`src/prayer/pray.eli`；时事采集：`src/prayer/oracle-news.eli`；话题与资料排序：`src/prayer/oracle-context.eli`；会话避重：`src/prayer/oracle-memory.eli`；入口：commands / presentation。测试覆盖请求与查询区分、关闭和熔断时零网络、引用校验、日期与域名范围、官方消息兜底和共享缓存、任务级熔断及业务状态不变；祝词还覆盖先记账后生成、身份隔离、超时、本地兜底及重复事件不重复调用。

实际验收需运行 CLI，并在已授权的 IM 会话中检查真人问题、机器人回复和引用链接；模拟网络成功不能代替平台收发。安装、重装、重启遵守 [运维步骤](operations.md)，同时更新核心与 Lark 二进制，不覆盖已有状态与订阅。
