# 多时间维度发言模型

状态：已实现。取代预测路径中最多八帖、逐批提取和随后多次研究/摘要请求的方式。策略版本 11。业务仍为纯 Eliscript，CLI、MCP、IM 共用同一结果。

## 必须存在的输入维度

AI 开启和关闭共用同一份历史基线、日历层及最终公式，只替换发言评分的提取器。本地规则提取不是另一套历史模型。

每次先从永久 ledger 按 ID 去重，排除未来帖子，保留全部已有重置记录。正文只存一份，窗口引用 ID，不重复发送正文。时间基准为本次 UTC 判断时刻；最新帖另有独立锚点。

| ID | 取数边界 | 模型含义 |
| --- | --- | --- |
| before_last_reset | 发布时间严格早于最近 global 完成 | 历史表达背景；不把已经兑现的旧话当成新机会 |
| after_last_reset | 发布时间严格晚于最近 global 完成 | 当前尚未兑现的候选事件 |
| last_48h | 判断时刻前 48 小时至当前 | 近期完整叙事、事故与计划变化 |
| last_24h | 判断时刻前 24 小时至当前 | 最新一日的决定和承诺 |
| latest_three | 最新三条可见发言 | 最新态度，是否撤回、完成或转为新的交付 |
| latest_anchored_24h | 最新一条发言前 24 小时至该帖，含端点 | 不因作者暂时沉默就丢掉最新一轮讨论 |
| official_context | 已取得的官方状态、新闻资料 | 事故背景与额度发布；不单独推出补偿重置 |

每个维度始终有 count、范围、完整性和数值评分。只有审计区间确实覆盖窗口才标完整；没有记录不是全网没有发言，缺失历史标 unknown。最近完成帖和有效每日计划作为独立背景保留，不因端点严格不等式而丢失。

## 无 AI 时间基础层

持久化保存所有历史 global/banked 日期、官方原文和出处等级；正常刷新只合并，不替换或清空历史。历史时间分布不足时可从公开互联网补录发现记录，再由官方原文核实；第三方分类不能直接变成官方完成。正常业务报告不出现发现站名称或概率。

时间输入包含逐次 epoch、间隔小时/天、最近若干次时间和间隔、当前等待时长、星期、月内日期、月初（1..10）/月中（11..20）/月末（21..最后一天）。同时保存 UTC、作者太平洋时区及配置统计时区的日历，风险积分遵循配置，端点仍用 UTC。基本历史模型继续计算条件剩余等待，不把已等待时间重算为完整新周期。

时间层保留四个基础候选并增加强收缩的近期节奏候选；日历包括星期、日期、阶段和日内时段，采用45/180天双尺度、桶支持度收缩和未来小时风险积分。模型权重按重置周期而非重叠时点评估，近期与长期误差共同作用。所有参数、公式、时区与降级契约见[动态时间层](adaptive-time.md)。
这一层不需要模型服务或搜索成功；消息增强失败仍可用。发言维度的已消耗、未核实与缺失状态也有本地数值降级，不跳过用户明确要求的窗口。

## 一次模型请求

一次 JSON 输入包含去重正文池、六个时间窗口的 ID、原始重置历史、当前周期、每日计划和官方资料。一次 JSON 返回每个维度的 support/opposition/commitment/imminence 分数（0..1），以及共享的少量带原文引用的发言解读。分数表示语言证据，不是 24h/48h 概率。引用必须来自对应窗口，原文、ID、枚举及范围由程序校验；未知或无证据为零。历史窗口的分数不直接制造未来机会。

正常预测的六窗特征只调用一次signals；独立研究、搜索计划并入这次输入，最终概率之后可选brief生成一句用卡理由，不再为窗口拆分调用模型；用卡文案预算独立且失败回退本地。模型出错不修复重试，直接使用相同维度的本地提取结果；其他人工聊天、翻译等能力不受影响。共享预测与评分缓存继续合并并发，缓存包含窗口成员及原文，状态和有效期每次重算。

## 概率公式和 Day 标签

Day N 是有效每日计划中的交付日标签，不是无意义数字。作者在 Day N 首句选择该日交付 reset（含 `reset day today`）是当期执行决定；它不自动证明已经完成，也不能仅凭标题就移动重置时钟。若另有本人落地时间回复（如 `Lands tomorrow before 10am PST.`），优先使用该期限，同时父帖、引用链及当前周期同批次语义承诺均计入有效窗口引用。只有 Day 标签时使用发布当天作者太平洋时区的日终作为估计交付窗口，明确记录为 programme-day；不伪装成作者给出的精确时区时刻。

历史承诺也记录 programme-day。后续经官方关系核实的本人回复首次补充真实期限时，保留原 Day 决定及估计边界，升级为实际期限，不算一次改期；再有改期仍增加修订次数，保留第一条真实期限，避免抹掉延期。历史解读只使用各帖发布时已经存在的前文，不给提取器后续结果。

程序先核实对象、当前周期和未撤回状态。只有未消耗的明确 global 决定/承诺才启用本次证据模型；一般暗示、事故和长期计划不靠少量样本随意加分。完成之后仍先重置时钟、消耗旧信号；新承诺单独计算。

近期五个窗口按 0.30/0.15/0.20/0.15/0.20 汇总语言证据，使用归一化平均而非独立概率相乘；同一事件多窗口出现不增加事件数。各窗口的有效贡献必须有当前周期原文，已兑现或仅历史引用不计。历史窗口作为旧信号负对照：近期评分混入重置前引用时，按未消耗引用比例折减；没有当前候选引用的窗口贡献为零。官方资料保留背景评分，不凭小样本独立增加重置机会。

在合格、审计完整的历史条件兑现估计不可用时，使用明示的工程先验 Beta(19,1) 表示明确交付决定的兑现倾向，转成先验赔率 19，由本次未消耗语言强度 s 折减一次：q=19s/(1+19s)。s 是五个近期窗口归一化后的支持强度，单窗 raw=max(0,min(1,support×(0.5+0.5×commitment)×(0.8+0.2×imminence)−opposition))，再乘未消耗引用比例。语义分数不是兑现率，不把相关分数当独立兑现机会连续相乘。时限与已经等待时间决定剩余交付质量。这个先验不是历史成功次数。交付时间分布沿用发布至期限的连续分布及延期尾部；条件在“尚未观察到完成”的前提下计算未来窗口的剩余质量 d_h。与原始历史基线 b_h 组合为 p_h = 1 - (1-b_h)(1-d_h)。不把已有承诺加权后的概率再次当基线。严格审计经验充分时优先保留历史条件估计，不假装小样本训练出了系数。

因此强证据且临近交付可能超过 90%，但不是凡见 Day 或 reset 就固定给 90%。逾期、撤回、证据陈旧、来源不完整和已完成会改变结果。所有六个维度的原始分数、有效分数、权重和实际贡献保留在本地 JSON，公开报告仍使用既定简洁模板。

## 已兑现信号的生命周期

每次先按发布时间去重、升序排列，过滤未来帖子，再统一合并已核实完成事件。最近 global 的时刻是硬边界；此前一次性承诺、暗示、意向和时间预期只属于旧周期。即使它们仍在最近 24h、48h、最新三帖或最新锚点窗内，也不能抬升下一次重置概率。后续真正的新承诺须晚于完成时刻，可单独生效。

不把概率固定扣成零：从新时钟重新计算相同历史基线、日历风险和当前未消耗证据。AI 不能撤销官方完成事实，故障降级也不能恢复旧加权。
