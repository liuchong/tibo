# 实时监测与订阅通知

## 固定行为

核心 daemon 正常每五分钟刷新公开资料。新原文或核实等级变化才触发一次共享预测；没有变化时只维护采集状态，原来的历史报告更新周期仍独立保留。所有订阅者复用同一条通知正文。

订阅包含三种通知：北京时间 09:00 / 21:00 定点预测、实时高概率/明确承诺预警、独立已重置确认。用户不能自定义时间或阈值。个人订阅投递到本人私聊，群订阅投递到显式订阅的群。

- 高概率：可用算法的 24h ≥70% 或 48h ≥85%，同一 global 周期只预警一次；不增加概率权重。
- 明确承诺：已核实、完整原文、global 对象、可解析期限，未兑现也未撤回；按公告去重，失效期限不预警。即使数值依据不足，也可提示这份明确承诺。
- 已重置：独立确认消息包含完成公告时间、原文和官方链接，不包含下一次重置概率。只有官方完整完成原文通过程序核实时才通知；AI 分类、banked 和个人自动刷新不能触发。

首次启动建立当前已知消息基线，不补发旧公告。后续新确认逐次入队；重启保留游标与通知状态。确认队列不因跨日或短时停机过期，恢复后继续投递。预警在承诺期限到期、生成一小时后（概率预警）或后续完成公告出现时失效。

## 限流与投递

五分钟是正常检查间隔，不是 X 的请求配额保证。公开页面与 X API v2 的额度不能混用。官方接口的限流返回和响应头含义见 [X 限流说明](https://docs.x.com/x-api/fundamentals/rate-limits)。所有 X 公开请求共用持久化退避：429 尊重 Retry-After 和 x-rate-limit-reset，403 及暂时失败逐级降频；冷却期间查询和定点任务同样不能绕开。并发采集仍通过共享缓存合并，已核实原文永久复用。不会使用代理或更换身份绕过限制。

核心只产生与平台无关的持久化通知。Lark 适配层消费通知并复用订阅注册表、Markdown 发送和投递回执。文字交互队列、定点分发和实时通知互不生成对方的报告。Lark 每十秒独立检查通知，定点报告生成不阻塞完成确认；订阅读写通过排队事务协调。投递前再次检查订阅；晚加入不接收旧通知。单个收件人失败不阻断其他人；发送结果未知时保留回执，避免盲目重复发送。
