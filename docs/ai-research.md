# AI 任务与预算

AI 是独立开关的结构化辅助，不是常驻 agent。它不访问文件、不操作账户，不把网页里的指令当成执行任务。固定命令和自有预测不需要模型；启动需要 API key 和对应功能名，两者缺一都不会调用。

## 十四项可选能力

功能名用于 `TIBO_AI_FEATURES`，也是本地诊断中的任务名。

| 功能 | 输入与产出 | 何时调用 | 输出 token 上限 |
| --- | --- | --- | --- |
| signals | 原帖 → 带逐字引用的分类与简释 | 有近 48h 原帖或期限内计划 | 1100 |
| search | 活跃相关原帖、已有资料 → 最多两个受限搜索计划 | 有相关未完成帖子 | 220 |
| research | 已抓资料、原帖 → 枚举化事实字段和关联 | 有资料或可分析的相关性 | 1400 |
| forecast | 历史基线、引用、分析 → p24/p48 建议 | 有活跃相关原帖 | 500 |
| review | 基线、建议、资料关系 → accept/reason | 大幅变化或矛盾，且该功能已开启 | 320 |
| brief | 证据、最终概率 → 简短摘要和跟进事项 | 有活跃相关原帖 | 650 |
| router | 当前业务问题、可见命令目录 → command/args/language | 固定解析未识别 | 280 |
| translate | 前序完整公开文本、目标语言 → Markdown | 显式翻译或语义跨语言展示 | 2800 |
| answer | 当前指令、可用前序文字、能力目录、可选匿名近期群背景 → 一次性回答 | 允许回复的业务 ask 或管道 ask | 1200 |
| repair | 当前错误片段、目录、语言 → 校验后的命令/管道 | 真实人工输入解析失败 | 400 |
| oracle | 当前问题、可选官方消息、少量匿名近期群背景 → 回复和内部引用校验 | 本地识别到角色请求且取得回复预算 | 380 |
| wish | 上香场景、随机变体与可选脱敏正文素材 → 一句含 token 的吉祥话 | 新祈祷已记账，调用预算 1.5 秒 | 160 |
| festival | 庆典主题、随机变体和脱敏素材 → 一句 token 祝词；图案由本地生成 | 允许回复且预留了集体彩蛋展示，预算 1.5 秒 | 240 |
| trigger | 当前群正文、命中关键词 → 各关键词相关度 | 允许回复的次级候选不明确、AI 任务未冷却，预算 1.2 秒 | 120 |

token 上限是输出额度，实际计费也包含输入。功能分别开启，不表示每次都调用十四项；预测最多经过六个任务，语义查询与文字管道有自己的调用阶段。

## 预测证据与校验

预测上下文最多含 8 条帖子，每条正文最多 1200 字符、引用上下文最多 400 字符；基础官方资料最多 6 条。预留最新帖，其余按证据价值选择：重置/发卡原文、声明期限内的计划、事故线索、最近两个已见 Day 的代表帖优先，闲聊只填剩余空位。计划原文可超过 48h，直到声明期限结束；已被后续 global 消耗的旧线索只作背景。采集 oEmbed 核实使用相同选取规则，避免仅核实最后几条闲聊。

还包含最近 global/banked、计划声明与到期时间、已见 Day 标签、压缩的历史统计与源健康情况。Day 子编号合并，不把“看到了更新”变成“确定没有重置”。`Or both` 表示可以并存；投票选项和父帖缺失时不编造上下文。signals 区分 reset-hint 意向与 global-promise 明确承诺，其 summary 随分类传给后续任务。等待按小时分桶，避免每次采集时间变化都使缓存失效。

所有输出要求严格 JSON，有限字段/枚举，引用必须是已提供资料中的原文。quoteText 是引用他人的上下文，不能归成 Tibo 的新承诺；截断内容不能补全。completion 分类不写历史。

research 的范围、完成状态、影响及事件关联进入后续 forecast，用于解释部分账户、已修复、重复或矛盾信号，但依然是推断。一次交付不能宣称整段多日计划已兑现；涉及计划声明的 fulfills 关联降为 clarifies，旧线索消耗由 global 时间规则决定。引用正确不保证归类正确，资料页也不能单独制造一个新 global 承诺。

概率融合与自适应条件见 [判断算法](decision-contract.md#ai-概率建议)，避免在这里复制第二套公式。

普通独立 ask 和管道 ask 只使用本程序提供的文字上下文，不读取外部概率或进行站点比较。独立 ask 询问最近重置、已过时间或到期时，先采集最近完成公告和 cycle，再把脱敏状态作为 text；纯概念问答不额外采集。模型失败保留可用状态。预测任务也收到 cycle 和最多 3 个不同重置事件的真实报告复盘；重叠报告不变成独立频率样本，7 天参考不变成 global 截止日。AI 输入与业务输出不包含内部发现源名称或地址；帮助、正文、JSON、MCP、翻译和原文管道遵守同一规则。

## 受限搜索

模型返回搜索计划，程序执行 Google / 百度公开页面请求，不需要搜索 API key 或 SDK。最多两个查询计划、两个可采用的原始资料；搜索获取总预算最多 12 秒，计入预测 AI 总预算。`scope=official` 查询官方页面，`scope=posts` 查询固定官方 X 账户；未指定 scope 保持官方页面方式，不接受模型自定域名或账户。

官方页面限固定 HTTPS 来源白名单（openai.com、www.openai.com、help.openai.com、status.openai.com），不接受任意主机，重定向不放宽边界。补充 X 公告只接受 `OpenAI`、`OpenAIDevs` 账户，使用官方嵌入接口核对作者和帖子 ID、由 ID 得到时间，要求近 48h、完整正文和具体 Codex 额度/重置/事故内容；不取得个人账户观察或陌生人的预测。它们只作补充材料，不能写入 Tibo 完成历史或替代 Tibo 原帖。

搜索摘要和链接列表不直接进入分析模型，必须成功抓取原始正文；页面获取时间不是发布时间，当前搜索原页不解析发布时间，该字段保留未知，因此不能作为公开报告的新事件引用。公开参考还须经过 [报告证据筛选](forecast-report.md#证据选择)，不是把研究资料全贴出来。

验证码、动态页面或网络拦截会导致 unavailable / empty，不能宣称已检索全网，也不绕过访问限制。搜索不能作为发现全部 Tibo 新帖的保证。失败或空结果缓存 15 分钟，成功取数缓存 6 小时。

## 交互文字与修复

翻译处理完整公开输出，不使用预测的“8 条 / 每条 1200”压缩规则。翻译输入上限 16000 字符，answer 前序文本上限 10000 并注明截断；AI 输出与最终展示限制见 [语言与管道](language-pipelines.md)。

router / repair 只接当前脱敏问题或失败片段及目录，不发送群历史、真实操作者、系统路径或前序结果。router 输出的命令和参数重新校验，不能绕过管理员白名单，也不能代确认。

repair 正常输入不调用，只处理真实人工解析错误；解析和执行共享预算。内部任务、MCP 结构化错误、权限拒绝与运行异常不触发。管道修复接着当前步骤执行，不重跑前序操作。

## 延迟、缓存与用量

- 预测六任务总预算 45 秒，含搜索；单次模型请求最多 15 秒，无即时重试。
- 管道文字处理总预算 30 秒，最多三步；人工修复最多两次、单次 10 秒，还受解析阶段的 45 秒截止与剩余管道预算限制。
- 任一任务序列化 evidence 超过 24000 字符时跳过，保留可用结果。
- signals/search/research 的模型结果缓存 6 小时，其他功能 20 分钟，最多 128 条；按提示词契约、任务实际输入和证据生成缓存键，命中也重新校验。
- router/repair 缓存包含用于理解相对日期的 UTC 业务时间；预测类缓存不因单纯采集时钟改变而全失效。

分析与文字处理使用 temperature=0，娱乐神谕 oracle 使用 temperature=1，祈祷祝词 wish 与庆典祝词 festival 使用 temperature=1.2；均关闭 thinking、只要求 JSON；这减少不必要输出，不保证完全确定。`ai-status` 记录各任务 calls、输入/输出 token 和最近延迟，不持久化模型思考或供应商错误体。

## 失败冷却

冷却跨进程重启保存，共享网关在独占锁下调用，防止同一状态目录并发探测。没有即时循环重试。

| 错误 | 暂停范围 | 当前策略 |
| --- | --- | --- |
| 401 / 403 | 全供应商 | 24 小时 |
| 402 | 全供应商 | 1 小时 |
| 429 | 全供应商 | Retry-After，最少 1 分钟、最多 24 小时 |
| 400 / 404 / 422 | 当前功能 | 6 小时 |
| 输出未通过校验 | 当前功能 | 连续第 2 次起 15 分钟 |
| 网络、超时、其他服务错误 | 全供应商 | 连续第 3 次起，1 分钟指数递增，最多 15 分钟 |

成功调用复位供应商和当前功能失败计数。密钥身份改变时使用新 AI 状态；文字契约升级只释放对应功能过期的结构校验暂停，不清除认证、限流或其他任务故障。

功能禁用、无有价值信息、预算不足、冷却中和实际请求失败是不同状态。预测正文不展示任务错误；语义查询或文字处理失败只给必要的简短提示并保留结果，具体错误分类留本地。AI 状态损坏或竞争也不能让核心算法崩溃。

## 本地观察与隐私

```bash
tibo ai-status
tibo diagnose
```

`ai-status` 显示当前开关、用量和最近失败；`diagnose` 是最近成功预测快照，含输入 postIds、selection 选择理由、programme 背景、资料、源状态和基线/建议/权重，不会重新调用。因此排查文字管道用 ai-status，核对最新预测资料用 diagnose；不要误把旧快照当作新执行证据。任务可用不表示概率必然改变，实际融合与整数变化只在本地 JSON 和诊断中查看。

预测与文字任务只上传需要的公开业务资料。配置、系统用户、目录、IM 身份、凭据和模型配置不进用户提示词或公开回复。调用 API 本身仍需要供应商认证和模型元数据，AI 是外部可选服务，不应把“无第三方运行库”解释成启用后不联网、不收费。

当前官方 API 参考：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[错误代码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes)。具体本地开关见 [配置参考](configuration.md)，失败定位见 [故障排查](troubleshooting.md)。

角色神谕使用独立的官方消息缓存与可选受限搜索；Anthropic 官方域名只用于该娱乐任务，不放宽预测搜索范围。完整触发、引用与降级规则见 [角色实现约定](oracle.md)。祈祷 AI 吉祥话使用 wish 独立开关、短预算和本地兜底，仅上传当前脱敏正文素材，不上传身份或个人档案，不重复记账。关键词过滤的门槛、成本与降敏规则见 [IM 触发过滤](im-triggers.md)。
