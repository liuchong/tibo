# AI 任务与预算

AI 是独立开关的结构化辅助，不是常驻 agent。它不访问文件、不操作账户，不把网页里的指令当成执行任务。固定命令和自有预测不需要模型；启动需要 API key 和对应功能名，两者缺一都不会调用。

## 十三项可选能力

功能名用于 `TIBO_AI_FEATURES`，也是本地诊断中的任务名。

| 功能 | 输入与产出 | 何时调用 | 输出 token 上限 |
| --- | --- | --- | --- |
| signals | 全部已存原文、六窗与历史 → 七窗评分和引用断言 | 正式预测一次调用 | 6000（独立逐帖接口1100） |
| search | 原帖线索 → 受限搜索计划 | 独立资料能力；正式预测不另调用 | 220 |
| research | 已抓资料 → 事实字段和关联 | 独立资料能力；预测资料并入 signals | 1400 |
| brief | 最终概率/程序倾向/相关公开证据 → 简短用卡理由 | 预测完成后可选一次，6秒超时；关闭或失败用本地分档 | 220（用卡任务） |
| router | 当前业务问题、可见命令目录 → command/args/language | 固定解析未识别 | 280 |
| translate | 前序完整公开文本、目标语言 → Markdown | 显式翻译或语义跨语言展示 | 2800 |
| read | 当前问题、直接引用、近期公开轮次、已确认主体、固定只读目录 → 至多三项查询 | 聊天取数需求理解，一次，不循环 | 600 |
| answer | 当前问题、应用背景、按需准备的公开资料或计算、可选引用 Thread 轮次 → 聊天；前序文字 → 管道处理 | 基础聊天或管道 ask | 1200 |
| repair | 当前错误片段、目录、语言 → 校验后的命令/管道 | 真实人工输入解析失败 | 400 |
| oracle | 当前问题、可选官方消息、少量匿名近期群背景 → 回复和内部引用校验 | 本地识别到角色请求且取得回复预算 | 380 |
| wish | 上香场景、随机变体与可选脱敏正文素材 → 一句短梗与一句 token 吉祥话；新事件不缓存成句 | 新祈祷已记账，调用预算 1.5 秒，两句共用一次请求 | 160 |
| festival | 庆典主题、随机变体和脱敏素材 → 一句 token 祝词；图案由本地生成 | 允许回复且预留了集体彩蛋展示，预算 1.5 秒 | 240 |
| trigger | 当前群正文、命中关键词 → 各关键词相关度 | 允许回复的次级候选不明确、AI 任务未冷却，预算 1.2 秒 | 120 |

token 上限是输出额度，实际计费也包含输入。功能分别开启，不表示每次都调用十三项；正式预测六窗最多一次signals请求，启用brief可另有一次220 token的用卡解释；语义查询与管道有独立阶段。

## 预测证据与校验

正式预测使用全部已存且不晚于当前时刻的去重原文，按时间排序。六个窗口引用同一个正文池，并附当前计划、历史时间向量和最多六条当前官方资料。所有窗口一次评分，不把八帖采集核实候选当作模型输入上限；正文没有逐帖3000字截断。完整边界见[多时间维度模型](dimensional-forecast.md)。

signals 输出支持、反对、承诺确定程度、时间接近程度及逐字引用，不输出正式概率。另有少量重要断言；分数、窗口和引用严格校验，可选断言坏行单独降级。完成事件仍由原文和来源关系确认，不凭模型标签移动时钟。模型失败使用本地同结构评分，历史和日历基线始终保留。

search/research不作为正式预测的后续模型阶段，诊断标merged或skipped；brief现用于最终概率的可选用卡解释，诊断保存实际成功/缓存/禁用/降级状态；原有开关不会替代 signals 开关。一般聊天、受限搜索和独立资料验证接口保留。旧 forecast/review 开关不产生请求，也不读取概率建议。公式由 forecast 计算，不凭小样本生成经验系数。详见[结构化特征](structured-features.md)和[判断算法](decision-contract.md)。

基础聊天使用应用背景和当前问题；Lark 明确引用时采用同一 Thread 的分角色历史，不引用时不带此前聊天。管道 ask 处理前序文字，不建立对话历史；角色问答可使用明确引用 Thread，并保留自身时事核实与话术约束。详见 [基础聊天与引用对话](chat.md)。ask 先由可选 read 理解当前问题和引用上下文，程序准备固定只读资料；重置业务由同一核心命令处理，正式概率仍由原算法生成。基础聊天还支持服务事故历史、搜索、计算、时区时间、日期和单位。普通聊天空计划不取数。模型失败保留可用状态与基本结果。预测任务也收到 cycle 和最多 3 个不同重置事件的真实报告复盘；重叠报告不变成独立频率样本，7 天参考不变成 global 截止日。AI 输入与业务输出不包含内部发现源名称或地址；帮助、正文、JSON、MCP、翻译和原文管道遵守同一规则。

## 受限搜索

官方事故资料记录首次公布、真实状态变化、恢复与采集时间；页面编辑、重复恢复和补发复盘不启动新事件时钟。仅明确处理中且有近期采集的事故作为当前背景，未知状态不等于仍在故障。事故后补偿有个别明确原始案例，但普通事故未显示稳定独立概率提升；目前不增加系数或固定加分。详见[事故关联研究](research/incident-reset-study-2026-10-14.md)。

模型返回搜索计划，程序执行 Google / 百度公开页面请求，不需要搜索 API key 或 SDK。最多两个查询计划、两个可采用的原始资料；搜索获取总预算最多 12 秒，计入预测 AI 总预算。`scope=official` 查询官方页面，`scope=posts` 查询固定官方 X 账户；未指定 scope 保持官方页面方式，不接受模型自定域名或账户。

官方页面限固定 HTTPS 来源白名单（openai.com、www.openai.com、help.openai.com、status.openai.com），不接受任意主机，重定向不放宽边界。补充 X 公告只接受 `OpenAI`、`OpenAIDevs` 账户，使用官方嵌入接口核对作者和帖子 ID、由 ID 得到时间，要求近 48h、完整正文和具体 Codex 额度/重置/事故内容；不取得个人账户观察或陌生人的预测。它们只作补充材料，不能写入 Tibo 完成历史或替代 Tibo 原帖。

搜索摘要和链接列表不直接进入分析模型，必须成功抓取原始正文；页面获取时间不是发布时间，当前搜索原页不解析发布时间，该字段保留未知，因此不能作为公开报告的新事件引用。公开参考还须经过 [报告证据筛选](forecast-report.md#证据选择)，不是把研究资料全贴出来。

Google / 百度无可用结果时，在剩余预算内依次使用固定 DuckDuckGo HTML、Bing RSS 查询，仍按相同官方来源白名单核实原页；后备不会扩大预测来源范围。验证码、动态页面或网络拦截会导致 unavailable / empty，不能宣称已检索全网，也不绕过访问限制。搜索不能作为发现全部 Tibo 新帖的保证。失败或空结果缓存 15 分钟，成功取数缓存 6 小时。

基础聊天的搜索是另一个固定只读方法：最多四条摘要和原始链接，默认继续读取最多两篇正文；只有标题或空摘要不能支持具体规则。搜索入口成功缓存 15 分钟、失败 60 秒，入口预算 8 秒；正文另有 18 秒共享预算、30 分钟缓存和条件重验证，详情见 [网页读取](design/web-reading.md)。官方服务状态读取固定 summary 和必要的 incidents 接口，成功缓存 60 秒、失败 30 秒；同类并发合并。read 是一次独立的输入语义解析，时限 6 秒；程序取数后 answer 只生成一次回答，没有模型 function call 或工具循环。read 的开关、缓存和失败冷却独立，关闭或失败不会阻断 answer；关闭 answer 仍可直接展示 read 取得的结果。详见 [内置信息能力](chat-builtins.md)。

## 交互文字与修复

翻译处理完整公开输出，不套用资料摘录的字符压缩规则。翻译输入上限 16000 字符，answer 使用完整前序文本并按共用上下文预算归档摘要；AI 输出与最终展示限制见 [语言与管道](language-pipelines.md)。

router / repair 只接当前脱敏问题或失败片段及目录，不发送群历史、真实操作者、系统路径或前序结果。router 输出的命令和参数重新校验，不能绕过管理员白名单，也不能代确认。

repair 正常输入不调用，只处理真实人工解析错误；解析和执行共享预算。内部任务、MCP 结构化错误、权限拒绝与运行异常不触发。管道修复接着当前步骤执行，不重跑前序操作。

## 延迟、缓存与用量

- 正式预测只请求一次维度评分，最多25秒、输出6000 token，不即时重试。输入按UTF-8字节保守上界970000计量，预留响应后低于1M；超限走完整本地维度，不删窗口。用卡解释至多额外一次brief，6秒、220 token，失败不重试；普通模型请求默认15秒。
- 管道文字处理总预算 30 秒，最多三步；人工修复最多两次、单次 10 秒，还受解析阶段的 45 秒截止与剩余管道预算限制。
- 普通任务的 evidence 与 conversation 合计超过 24000 字符时跳过。多维预测、持久引用聊天及其摘要使用独立预算，不受这项小任务限制；详见聊天文档。
- 独立逐帖接口保留永久事实缓存；正式多维预测使用网关缓存。网关 signals/search/research 响应缓存6小时，其他功能20分钟，最多128条；缓存身份包括契约和实际输入，命中重新校验。
- 交互预测还有核心结果缓存：从采集时间起两分钟内共享整份判断，并合并同时到达的生成请求。命中会跳过采集与整个预测 AI 流程，语言和后续管道仍单独处理；已知证据、经验及相关 AI 配置/冷却变化提前失效。无 AI 结果与 AI 结果分开，定点报告、离线及指定快照不使用这层缓存。
- router/repair/read 缓存包含用于理解相对日期的 UTC 业务时间；多维预测包含时间桶、窗口边界和时间分布输入，不能跨新周期沿用旧分数。

分析与文字处理使用 temperature=0，娱乐神谕 oracle 使用 temperature=1，祈祷祝词 wish 与庆典祝词 festival 使用 temperature=1.2；均关闭 thinking、只要求 JSON；这减少不必要输出，不保证完全确定。`ai-status` 记录各任务 calls、输入/输出 token 和最近延迟，不持久化模型思考或供应商错误体。

## 失败冷却

冷却跨进程重启保存。共享网关只在请求准入和结果合并时用短状态事务；网络请求在事务外并行执行，慢预测不会占住祝词或聊天请求，也不会仅因已有调用就降级。完成时重新读取最新状态，合并各功能用量与缓存；旧的成功不能清除并发产生的新失败，较弱的失败不能缩短仍有效的较强冷却。AI 状态重置或凭据更换后，旧请求不得写回新状态。冷却建立前已获准的请求仍可结束，后续请求按冷却阻断；没有即时循环重试。并发总量由接入层工作队列限制，不添加模型工具或任意命令执行能力。

| 错误 | 暂停范围 | 当前策略 |
| --- | --- | --- |
| 401 / 403 | 全供应商 | 24 小时 |
| 402 | 全供应商 | 1 小时 |
| 429 | 全供应商 | Retry-After，最少 1 分钟、最多 24 小时 |
| 400 / 404 / 422 | 当前功能 | 6 小时 |
| 输出未通过校验 | 当前功能 | 连续第 2 次起 15 分钟 |
| 网络、超时、其他服务错误 | 全供应商 | 连续第 3 次起，1 分钟指数递增，最多 15 分钟 |

成功调用复位供应商和当前功能失败计数。密钥身份改变时使用新 AI 状态；文字契约升级只释放对应功能过期的结构校验暂停，不清除认证、限流或其他任务故障。

功能禁用、无有价值信息、预算不足、冷却中和实际请求失败是不同状态。预测正文不展示任务错误；语义查询或文字处理失败只给必要的简短提示并保留结果，具体错误分类留本地。AI 状态损坏或竞争也不能让核心算法崩溃。

## 本地观察与隐私

```bash
tibo ai-status
tibo diagnose
```

`ai-status` 显示当前开关、用量和最近失败；`diagnose` 是最近成功预测快照，含输入 postIds、selection 选择理由、programme 背景、资料、源状态、结构化特征、基线和特征模型门槛，不会重新调用。因此排查文字管道用 ai-status，核对最新预测资料用 diagnose；不要误把旧快照当作新执行证据。任务可用不表示概率必然改变，模型是否应用及降级原因只在本地 JSON 和诊断中查看。

预测与文字任务只上传需要的公开业务资料。配置、系统用户、目录、IM 身份、凭据和模型配置不进用户提示词或公开回复。调用 API 本身仍需要供应商认证和模型元数据，AI 是外部可选服务，不应把“无外部运行库”解释成启用后不联网、不收费。

当前官方 API 参考：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[错误代码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes)。具体本地开关见 [配置参考](configuration.md)，失败定位见 [故障排查](troubleshooting.md)。

角色神谕使用独立的官方消息缓存与可选受限搜索；Anthropic 官方域名只用于该娱乐任务，不放宽预测搜索范围。完整触发、引用与降级规则见 [角色实现约定](oracle.md)。祈祷 AI 吉祥话使用 wish 独立开关、短预算和本地兜底，仅上传当前脱敏正文素材，不上传身份或个人档案，不重复记账。关键词过滤的门槛、成本与降敏规则见 [IM 触发过滤](im-triggers.md)。

普通聊天 answer 使用单次 Markdown 正文返回，由程序封装文字和校验隐私/数字；兼容历史单 text JSON 包装。无需让模型把自然语言另转成 JSON，read 等结构化计划仍严格 JSON 校验。该调整不增加模型请求或执行入口。
