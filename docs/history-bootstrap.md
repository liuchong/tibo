# 历史时间线与安装预填充

`data/history/ledger.json` 是随版本保存的公开历史数据。它与服务维护的 `ledger.json` 使用同一种结构：`schemaVersion: 1`、`now`、`events`、`posts`、`documents` 和 `timeline`。它只供安装、迁移和维护使用；预测、CLI 查询、MCP、Lark 和 daemon 不导入这份仓库文件，也不把它作为启动时的后备数据源。

## 数据口径

- `posts` 保存官方原帖、UTC 发布时间、作者、核实来源、截断状态与可核实的引用关系。
- `events` 保存已经确认的 global / banked 事件。global 为 true 才能推进历史时钟；未来预告不能写成完成事件。
- `timeline` 保存所有相关公告，包括 `announced`（预告）、`processing`（执行或传播）、`completed`（完成表述）、`hint`（暗示）、`conditional`（条件计划）及独立的 `banked` 类别。同一次发放的多条原帖可以出现在时间线中，不能据此重复计算实际重置次数。
- `now` 是这份资料累计到的时间；安装不会把旧资料改成“刚抓取成功”。公告发布时间不等于每个账户实际生效时刻。
- `documents` 在公开安装资料中为空；不发布实例中的运行资料、私有配置、订阅、聊天、祈祷档案、回执或预测经验。

初始版本包含 55 组 global 相关公告。其中 35 组存在已重置表述，12 组是执行/传播表述，8 组只有预告。后两类保留为消息和时间线，不人为补出完成时间。官方短帖的主题由公开上下文核对；预填历史不伪造 parent/quote 关系。已公开的两条近似重复公告合并为同一次事件；原帖仍分别保存。

仓库仅保留官方原帖地址。维护时可以核对公开存档来发现遗漏，但提交前应追溯官方帖子、核实作者/ID/时间，剔除非官方网址、接口和发现来源元数据。无法确认的观测不升级成完成事实。

## 安装及重装

```bash
bun install
bun run compile
.tibo/bin/tibo service install
```

编译产物包括两个独立可执行文件及 `.tibo/bin/history/ledger.json` 侧车文件。发布时把 `history` 目录与核心程序一起分发。安装器在启动核心服务前校验并导入侧车；不会将历史嵌入二进制。

也可明确指定安装历史：

```bash
.tibo/bin/tibo service install --history data/history/ledger.json
```

安装使用配置中的实际 `TIBO_STATE_DIR`。全新实例直接获得历史；旧实例按条目 ID 只补缺项，已有同 ID 原帖、事件、较新数据时钟及其他实例状态优先保留；只补入经核对的缺失 `sameResetAs` / `replacesEventIds` 关联。重复公告共享同一个事件身份；官方完成公告取代早先观测的计数地位，观测原记录仍保留。读改写使用与采集相同的 ledger 事务锁，写入采用临时文件加原子替换；连续导入不会重复追加。导入收据保存到运行目录的 `history-install.json`。已核对的历史完成表述使用 `completionBasis: reviewed-public-announcement` 记录，保留官方作者、原帖 ID、时间及地址，不伪造引用关系；模型核对这些字段后将其视为已核对历史。已有实时监测实例会把这批历史帖子的 ID 合入已知列表，避免重装后向订阅者补发旧重置确认。

Lark 安装不重复导入；服务普通启动、重启和预测不会重新读取安装数据。删除仓库文件不影响已导入实例继续工作。不要通过覆盖整个状态目录来“更新历史”。

## 非 macOS 或仅使用 CLI

显式执行一次本机安装步骤，然后正常使用：

```bash
bun bin/tibo.mjs history-seed install data/history/ledger.json
bun bin/tibo.mjs forecast --offline --no-ai
```

这两个本机维护动作不在模型命令目录、MCP 工具或 IM 业务命令中注册。机器人不能通过提问、管道或 AI 路由调用导入、导出或任意文件路径。

## 服务自主维护与仓库更新

服务继续按既有五分钟检查周期读取官方主页和相关原帖，复用共享缓存、并发合并、请求预算和限流退避。新原文、已确认事件与时间线在同一份运行时 ledger 内持续保存；网络或 AI 不可用时保留已有历史。服务不会请求安装时的资料提供站点，也不会写 Git 仓库。

仓库安装快照每周维护一次。维护人员或已授权定时任务先让运行实例正常采集，再导出公开字段：

```bash
tibo history-seed export data/history/ledger.json
```

导出只保留固定公开字段并清理非官方链接；不能把活动 `ledger.json` 本身指定成导出目标。旧事件只有在运行时已有完成状态或对应完成时间线时才进入导出事件集；未确认类型标签保留在消息和时间线中。导出结果先核对 diff：不能把预告改成完成、不能倒退已知时间或丢掉已发布历史；必要时补查官方原帖。无变化无需提交；有变化运行数据契约测试后签名提交、推送。运行实例有私有数据，不能直接复制它的 ledger 文件进仓库。

定期维护只是刷新给未来安装使用的快照，不影响已运行实例的实时采集。维护任务失败时保留上一版；不清空数据或猜测完成时间。
