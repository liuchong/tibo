# 会话接入与通知边界

## 三个独立范围

| 配置 | 默认值 | 职责 |
| --- | --- | --- |
| `TIBO_LARK_CHAT_IDS` | `all` | 被动群交互；也可填写逗号分隔的群 ID，或留空关闭群交互 |
| `TIBO_LARK_ADMIN_CHAT_IDS` | 空 | 管理员可以操作的群，必须明确列出群 ID，不支持 `all` |
| `TIBO_LARK_NOTIFY_CHAT_IDS` | 空 | 报告与实时通知的群订阅，必须明确列出群 ID，不支持 `all` |

机器人加入群且平台交付事件后，`all` 允许查询、祈祷、轻量表情等普通功能。仍执行点名、关键词相关度和回复节奏规则；不是每条消息都回复。群接入不自动赋予管理权，也不自动订阅报告。

系统管理操作同时要求本应用可信管理员身份，以及管理员私聊或明确配置的操作群。群订阅另有本群管理权限，不会授予清空历史、经验或修改系统状态的权限。确认 ID 仍绑定申请人、会话、应用和五分钟有效期。

`subscribe`、`unsubscribe`、`subscription` 在任何群或私聊默认针对本人私聊订阅，效果相同；可显式加 `personal`。不能代他人订阅或自定义时间。

显式加 `group`，或语义明确要求“往本群提醒”，才是群订阅。目标群的群主或用户管理员可在本群使用 `subscribe group`、`unsubscribe group` 申请，随后由同一人在本群发送 `确认 ID`；`subscription group` 查看状态。不要求本群属于系统操作群。角色由 Lark 官方群信息接口读取，申请与确认分别重新查询，不能使用消息中自称的管理员身份；普通群成员不能开通，角色撤销后原申请不能确认。该权限仅限本群，不能指定其他群或在私聊代管。

Tibo 系统管理员原有的私聊或操作群管理入口保留，可明确指定群 ID 管理订阅；系统管理员白名单和危险命令权限不扩大。AI 只能解析申请，不能代为确认。普通订阅仍默认本人私聊，不能自定义推送时间。

引用消息中的明确订阅请求也先走语义业务路由；普通引用追问仍进入聊天并使用引用上下文。语义路由只根据本轮请求发起操作，不执行旧消息或机器人建议。带🙏的消息仍拆成独立上香与订阅任务，谁先完成谁先发送。

### 本次验收清单

- [x] 群主、群管理员可申请并确认本群订阅；普通成员、跨群、跨人、角色撤销及接口失败不能确认。
- [x] 群管理身份不能调用 Tibo 系统管理；原系统管理员权限与已配置订阅保持。
- [x] 实际语义请求与引用请求路由到群订阅，上香并行完成，申请本身不启用订阅。
- [x] 文档与验证同步；真实角色 API 和实际模型复测使用隔离订阅数据与本地投递捕获，不向生产会话发送测试消息。

交付时先运行完整测试，再签名提交并推送，按 [安装与运维](operations.md#更新与重装) 重装核心与 Lark 两个服务。重装不替用户确认旧申请，不更改既有生产订阅。

## 统一会话订阅

核心订阅记录包含 `kind`、`id`、`active`、`revision`、`updatedAt`。群订阅的 `kind=group`、`id=chat_id`；个人私聊订阅的 `kind=dm`、`id=actor`，由接入层用平台用户 ID 向本人私聊投递。群与私聊使用不同接收者类型，不能用群 ID 向私聊接口发送，也不能把用户 ID 当群 ID。

通知配置在启动及建立定点发送计划时同步为群订阅。配置新增群会激活订阅；删除配置来源的群会停用它，不删除祈祷档案。命令管理的群订阅独立保留：确认退订后，配置未变化时不会重新开启；配置移除再添加视为新的明确订阅。命令新增的群不因配置列表没有它而被删除。旧个人订阅保持身份、订阅状态和生效时间，读取时转换成统一结构。所有记录按接入应用隔离。

命令创建或恢复的个人、群订阅从下一定点接收定点报告，实时通知从订阅后生效；配置群纳入下一份新建的通知计划。已保存计划不追加后来新增的收件人。

定点报告每天服务配置时区 09:00、21:00 生成，每定点只有一份，订阅数量只影响发送数量；另外共享实时预警和独立完成确认，详见 [实时通知](realtime-alerts.md)。发送计划保存接收会话和订阅 revision，发送前重新核实；已取消、移除或重新订阅的旧 revision 不投递。重启不重发，错过定点不补发，失败不重新生成报告。`all` 从不展开成通知接收群。

## 配置与升级

```dotenv
TIBO_LARK_CHAT_IDS=all
TIBO_LARK_ADMIN_CHAT_IDS=oc_操作群
TIBO_LARK_NOTIFY_CHAT_IDS=oc_接收群
TIBO_LARK_ADMIN_OPEN_IDS=ou_管理员
```

三个范围互相独立。使用显式被动群列表时，要把需要群内交互的操作群也列入；通知群无需允许被动交互即可接收报告。旧版本把一个群列表同时用作接入、管理与推送；升级时将操作群和原有报告群分别填入新增配置，保留个人订阅档案。只修改配置后重启 Lark 服务，不需要重启核心采集服务。

私人配置与群、用户的真实标识不提交到仓库。安装、重装与重启命令见 [安装与运维](operations.md)。
