# 内置信息能力

Tibo 先理解用户想得到的答案，再准备固定只读资料，最后综合回答。电话、日期、规则或比较问题直接给所问结果；只有用户明确要求搜索结果清单时，才直接展示搜索资料。普通常识、解释和翻译不强制联网。

## 一次理解、一批读取、一次回答

固定命令不需要 AI。一般事实问题进入 `ask`；`read` 根据本轮问题及显式引用历史，输出最多三个规范只读查询。程序整体校验后并发执行，再交给 `answer` 一次性回答。多个时间或换算对象分别准备数据，由同一次回答汇总。

没有引用的消息不带旧聊天；引用追问沿真实用户主问题继续，机器人附带建议不能擅自改变主题。正规历史、摘要与原文卸载见 [基础聊天](chat.md) 和 [容量设计](chat-context-design.md)。

这不是工具调用循环：模型不能定义方法、发送下一批计划、执行命令、选择本地文件或修改账户。`context-read` 只读程序提供的当前会话原文归档，不接受任意路径。具体边界见 [AI 与执行边界](execution-boundary.md)。

## 方法目录

| 方法 | 数据与用途 |
| --- | --- |
| `forecast/status/posts/history/banked/signals/stats/review/help` | 现有公开业务资料及命令说明 |
| `service-status/service-history` | 官方服务状态、组件及事故历史，与重置公告区分 |
| `search/read-page` | 多路搜索、网页原文与来源核对 |
| `calculate` | 有限浮点数、括号、四则、取余和幂；固定解析器，不执行代码 |
| `time` | 当前或给定 UTC 时刻的 IANA 时区时间，含夏令时 |
| `date-diff/date-add` | 日期间隔与整数时长推算；一天为 24 小时，一周为 7 天 |
| `convert` | 长度、质量、时长、数据容量及温度；不是汇率工具 |
| `place` | 用户明确提供的城市、地区或邮编的公开候选坐标和时区 |
| `weather` | 用户给定城市或坐标的当前温度、风速与未来 1–7 天预报 |
| `distance` | 两个城市参考点或给定坐标间的球面距离，不是驾车路线 |

参数、范围和示例见 [命令参考](commands.md)。城市名和 ISO 两字母国家代码分开传入（如 `place Sydney --country AU`），避免名称混拼造成空结果。城市有重名时核对国家与行政区；天气及距离取第一候选时会保留实际选中地点。程序不读取设备定位或依据 IP 推断用户位置。

## 搜索与核实

Google 和 Baidu 并行查询并合并结果；可用结果不足两个不同域名时，在剩余总预算内并行使用 DuckDuckGo 与 Bing。按 URL 去重，最多保留八条，记录检索入口和采集时间；同一网页被多个引擎找到仍只是一份材料。

每个搜索默认读取最多三个不同域名的正文，优先文档及支持页面，共享 14 秒正文读取预算。`read=false` 只返回搜索摘要。单个网页遵循 [网页读取设计](design/web-reading.md) 的公网校验、2 MB 响应上限、静态提取、按需 WebView 与失败处理。JSON-LD 中的商户名称、电话、地址和营业时间也作为网站自述资料保留；标题中的 HTML 实体会解码。

需要精确或易变事实时，一批计划可使用两至三个互补查询，围绕同一实体、门店或规则寻找官方直接资料及独立来源。一般常识不机械凑查询次数，已经有充分可靠的直接来源也可以回答。日期、来源身份、是否同一家门店和转载关系，比网址数量更重要；不同域名也不自动代表独立证实。

回答先给结论，再给必要的简短依据及一至两个原始链接。明确区分正文、部分正文、搜索摘要与旧知识；来源矛盾时核对对象与更新时间，不能按票数决定事实。网页访问受限或资料不足时如实说明，不声称已经核实。

## 缓存与故障

| 数据 | 成功缓存 | 失败或空结果 |
| --- | --- | --- |
| 每个引擎的搜索 | 15 分钟 | 1 分钟 |
| 网页最新指针 | 30 分钟；正文快照按内容哈希保存 | 1 分钟 |
| 城市候选 | 1 天 | 30 秒 |
| 天气 | 10 分钟 | 30 秒 |

各方法通过状态事务合并并发读取。城市与天气使用无需 API key 的 Open-Meteo 公开接口；城市数据署名 GeoNames，每次网络请求最多 5 秒。网络不可用不影响本地日期、时区、单位和算术；离线模式不查询地点或天气，明确坐标间距离仍可计算。

`read`、`answer`、`router` 各有独立开关和冷却。资料准备失败不触发关键词猜测或多轮重试；最后回答仍可解释已有材料。AI 回答失败时保留已取得的确定性资料，错误不带供应商正文、私有配置或环境信息。

## 试用与回归

公开的跨领域问题、核对要点及实际试用方法见 [问答样例](qa-examples.md)。私有会话只用于本地核对，不进入样例或测试。自动测试检查资料合并、共享读取、结构化字段、离线行为和无模型工具请求；真人问题的事实正确性另按来源核对，不把请求成功当成答对。
