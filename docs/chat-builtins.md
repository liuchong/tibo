# 引用修复与内置信息能力

## 行为和边界

基线为 599bebf。已核实的缺陷是通用技术说明被整段替换成敏感占位文本；引用本身已识别，但正文缺失。另一个缺口是一般聊天没有连接现有的信息采集能力。

对话历史只脱敏实际值，保留正常技术语义。对旧占位轮次，按本地源消息标识与重新核实的原文修复；有效轮次保持追加顺序，已摘要卸载的历史不重新灌入。来源标识不进入模型。

程序在回答前准备所需资料：官方 OpenAI 服务状态、公开搜索结果、确定性算术和 UTC 时钟。引用追问只使用当前问题与相关历史确定查询主题；普通未引用问题仍是单次请求。历史不执行命令，也不赋予权限。

搜索使用固定 Google、Baidu 入口，脚本或验证页不算结果；必要时依次使用 DuckDuckGo HTML、Bing RSS 后备。最多四条公开结果，查询共享缓存和并发合并；结果链接只用于引用，不作为任意网页抓取入口。搜索摘要明确标识，不当成已经核实的原文；预测资料仍按原有官方来源范围过滤。官方状态单独读取固定 API，短期共享缓存。

算术使用程序内解析器，限制长度、符号、深度和数值，只计算数字与运算符，采用有限浮点数，支持括号、四则、取余和幂；不使用动态求值或执行代码。资料不可用时明确保留未知；AI 不可用时仍展示已取得的状态、搜索结果或计算结果。离线输入不联网。

这些是固定程序方法，不是模型可调用的通用工具。请求中没有工具目录，不接受 function_call / tool_calls，不运行系统命令，也没有多轮工具循环。此前版本一般回答只请求一次模型，但能力准备依赖少量句式；本次语义接入替代此限制，见下文。容量摘要保留既有独立机制。

## 长正文请求修复

语义路由选择 ask 时只需返回空 args，由程序填入完整用户输入；避免小输出预算重复长文。重放原始富文本与引用链时仅使用隔离状态、不补发旧回复。测试核对超过旧上限及旧管道总长度的正文、末尾内容、无引用语义路由，以及超限时无模型和无查询调用。
