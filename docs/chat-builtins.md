# 引用修复与内置信息能力

## 行为和边界

基线为 599bebf。已核实的缺陷是通用技术说明被整段替换成敏感占位文本；引用本身已识别，但正文缺失。另一个缺口是一般聊天没有连接现有的信息采集能力。

对话历史只脱敏实际值，保留正常技术语义。对旧占位轮次，按本地源消息标识与重新核实的原文修复；有效轮次保持追加顺序，已摘要卸载的历史不重新灌入。来源标识不进入模型。

程序在回答前准备所需资料：官方 OpenAI 服务状态、公开搜索结果、确定性算术和 UTC 时钟。引用追问只使用当前问题与相关历史确定查询主题；普通未引用问题仍是单次请求。历史不执行命令，也不赋予权限。

搜索使用固定 Google、Baidu 入口，脚本或验证页不算结果；必要时依次使用 DuckDuckGo HTML、Bing RSS 后备。最多四条公开结果，查询共享缓存和并发合并；结果链接只用于引用，不作为任意网页抓取入口。搜索摘要明确标识，不当成已经核实的原文；预测资料仍按原有官方来源范围过滤。官方状态单独读取固定 API，短期共享缓存。

算术使用程序内解析器，限制长度、符号、深度和数值，只计算数字与运算符，采用有限浮点数，支持括号、四则、取余和幂；不使用动态求值或执行代码。资料不可用时明确保留未知；AI 不可用时仍展示已取得的状态、搜索结果或计算结果。离线输入不联网。

这些是固定程序方法，不是模型可调用的通用工具。请求中没有工具目录，不接受 function_call / tool_calls，不运行系统命令，也没有多轮工具循环。此前版本一般回答只请求一次模型，但能力准备依赖少量句式；本次语义接入替代此限制，见下文。容量摘要保留既有独立机制。

## 语义只读能力接入（当前施工）

起点 abb4eba。引用历史已完整，但状态追问换一种措辞后不会采集；服务状态的已解决事故被过滤，且聊天目录只是说明文字。当前授权是修复语义能力连接、补齐常用只读能力、真实隔离试用、文档、签名提交推送和重装。

固定输入命令仍直接运行。聊天先做一次受限语义解析，结合当前问题和引用链输出最多三个固定只读查询；程序校验整个计划后并发取数，再做一次回答。普通聊天输出空计划。这里是独立的输入理解和单次回答，不使用 API tools/function_call，不循环请求模型、不接受下一步计划。AI 无法定义方法、身份、URL、文件或系统命令。read 失败独立冷却，answer 仍能聊天；answer 关闭时保留读取结果。

语义目录包括既有公开预测、发言、状态、历史等只读业务，以及官方服务状态、事故历史、搜索摘要、数字算术、时区时间、日期间隔与单位换算。服务历史与重置历史是不同类型。历史问法应依当前对话主题解释，此前实际成功取数的主体随确认轮次保存并跨摘要保留；仅由当前用户明确换题才能切换，计划需给出当前原句佐证。当前用户优先于旧机器人错误引导。没有引用不读历史；计划模型只取公开问题、直接引用、少量近期角色内容和摘要，完整回答沿用原有正规会话管理。来源 ID 和身份不进入模型。

能力解析由独立 read 开关控制，输出预算 600 token、时限 6 秒；失败不重试、不用关键词猜意图，保留普通聊天并标明此次查询未准备成功。固定只读命令在无 AI 时可用。数据获取有缓存、并发合并和超时；资料或最终回答失败时保留已取得的确定性结果。计划结果不作为历史事实，取数结果带来源、时间和失败状态。
