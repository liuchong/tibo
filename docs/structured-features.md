# 结构化消息特征与降级

当前策略为 10：AI 提取消息含义，程序校验、管理状态并计算概率。正式预测不请求 AI 概率，也不融合 AI 概率建议；旧 `forecast`、`review` 开关和 `TIBO_AI_WEIGHT` 已停用，原配置可保留但不产生调用或权重。

官方事故是独立辅助资料，不能直接当作重置补偿。当前未启用事故固定加分；[历史研究](research/incident-reset-study-2026-10-14.md)确认少量明确补偿案例，普通事故没有稳定的独立提升证据。资料按真实状态变化时间选取，页面编辑、重复恢复和复盘不变成新事件；原始公布、恢复和采集时间分开保存。处理中事故须有近期采集，未知状态不能当 active。此修正不改变数值权重。

## 当前链路

1. 统一完成事件先更新时间起点，计算原有历史曲线及收缩的日历风险；AI 开关不会移除基础层。
2. 永久原文按 ID 去重、发布时间排序；六个必需窗口引用同一正文池，不再只给八帖。
3. signals 一次请求返回六窗与官方资料的数值评分，另提取最多十个重要帖、每帖最多两个断言。只提供公开时间、原文、核实关系和历史数值，不提供私人会话或配置。
4. 分数为0..1并要求窗口内逐字引用；所有窗口缺一则降级。可选断言逐帖校验，坏行回退规则，不让一条坏断言抛弃其余有效评分。不即时修复或再请求。
5. 断言状态由程序重算。Day N 的交付选择和真实完成分开，后续自回复期限优先，完成之前的旧信号始终消耗。
6. 明确交付决定走自有条件交付公式；一般暗示、事故、发布仍不凭小样本任意加权。严格审计的承诺历史充分时优先使用条件兑现估计。

完整窗口、评分、时间分布与公式见[多时间维度模型](dimensional-forecast.md)和[数值预测](numeric-forecast.md)。

AI 的 `completion` 分类不能单独写入事件历史或移动时钟。完成公告核实使用原文和来源关系；按句识别明确相邻句衔接，不让无关的将来时结束语否定完成公告。明确 reset 对象后紧邻的 “It’s done” 等代词完成句可核实；“Done and dusted”等省略对象的完成短句，须有官方核实的本人引用/自回复链补齐 global 对象。最多沿三层关系，不能把相邻发言、条件、否定、banked、周周期或其他作者的引用当成完成。截断帖不能取得完成核实等级。

统一事件层在历史模型、承诺策略和特征状态计算之前合并这些完成事实。完成之前的一次性承诺、暗示及时间预期成为 consumed，不再恢复旧承诺的概率；完成之后的新承诺仍可独立参与。对同一预告的重复完成短句不重复推进时钟。持续计划保留背景；完成关系按原帖时刻核实，计划后来过期不会抹掉已确认的完成。AI 开启和关闭使用相同完成事实；AI 特征携带公开作者与核实的关系对象，避免在文字脱敏准备时丢掉完成所需依据。

## 提取记录

AI 输出 `rows[{postId, claims[]}]`。每个 claim 只允许以下字段：

| 字段 | 内容 |
| --- | --- |
| `kind` | promise、hint、incident、programme、progress、release、completion、negation、other |
| `subject` | codex-usage、chatgpt-work-usage、product-change、personal-task、unknown |
| `scope` | global、banked、partial、unknown |
| `statement` | future、completed、conditional、negated、unknown |
| `quote` | 本帖正文的连续原文，校验上限 220 字符 |
| `timeText` | 原文时间词或 null；不允许模型直接填写 UTC |
| `timing` | 时间预期 `{stance,window,amount,zone}` 或 null；与 `timeText` 和原文引用绑定 |
| `contextMissing` | 是否缺少解释所需对象或父帖 |

程序补 `claimIndex`、引用位置、来源等级、提取版本和 `knownAt`，再增加 `targetAt`、`timePrecision`、`expiresAt`、`status`、`episodeId`。时间必须与同一断言引用对应；`by EOD PST/PDT/PT` 及 end-of-day 表达解析为当地次日零点这个上限，`timePrecision=deadline`；EOD 未明示时区仍保留 unresolved。PST/PDT 使用明确固定偏移对应的发帖日期，PT 按旧金山夏令时。关系只使用程序已知的父帖、计划和明确 `fulfilledPromiseId`；AI 资料关联仅供解释，不自行兑现承诺。

数值候选为 promise、hint、incident、programme、timingExpectation 五个特征。progress、banked、release 保留在结构中，暂不添加独立系数。同周期同类线索只表示特征存在，不按帖子数量累计加分。没有完整消息覆盖或有未提取、截断行时，缺失特征是 null，不能当成零。

### 语义化时间预期

提取契约为 `post-claims-3`。同一次逐帖 AI 调用理解作者的态度、时间范围、转折和指代，不增加另一轮概率请求。`stance` 区分 commitment（明确承诺）、expectation（预计）、intention（希望或打算）、possibility（可能）、conditional（二选一等条件计划）、negated、unknown。预计、打算和可能归为 hint，日期本身不能将其升级为明确承诺。规则层也防止把带 probably、should、hope 等明显不确定措辞的期限预告写入确定承诺历史。直接、无条件的 global/full reset 落地公告保持 commitment；AI 和缓存不能仅因将来时态将其降为 expectation。

`window` 为 within-hours、within-days、today、tomorrow、soon、this-week、next-week 或 unspecified。`timeText` 必须逐字包含在本帖引用中；“午饭前”等模糊表达可以保留原文和 unspecified。`amount` 仅显式数字小时/天可用，最多 720 小时或 30 天；猜测的数字清空。`zone` 仅接受原文写出的 PST/PDT/PT/UTC，否则 unknown。模型不填写 UTC，不补默认时区。

程序解析可核实的相对窗口、明确时区的当地日期窗口或已支持的精确时间；保存在 `expectedWindow.from/through/resolution`，并与正式承诺的 `targetAt` 区分。预计时间过去记为 expectation-passed，不冒充确定承诺违约。soon、无时区的 tomorrow、下周、午饭前等仍是 unresolved，进入引用和解释，不给定量窗口。其存在不能作为精确时间特征的已知值。

无主语的短回复只有在快照中存在同作者、已核实、早于回复的来源关系时，才提供这份上下文；直接父帖，或官方核实的引用接自回复链，均可补齐对象。未核实父帖、引用别人的文字或缺失对象不能推定 global。选择阶段优先保留相关自回复，仍限最多八条输入。明确相对期限可保留到对应期间结束；this-week/next-week 背景最多保留 7/14 天，这只是上下文保留期限，不是 UTC 截止时间或重置保证。后续 global 消耗一次性预期。

`timingExpectation` 仅针对完整官方原文、对象属于额度、global/unknown 范围的有效非确定时间预期。未解析的预期令该维度为 null；已解析的窗口只在与六小时风险段相交时启用。不按帖子数量累计。系数仍须通过下述审计、样本和独立时间验证门槛；没有合格模型时，只补充证据和理由，数值不加分。AI 关闭或失败时，有限规则提取仍保留可识别的时间预期，其余明确未知。

`forecast.timingAssessment` 记录有效预期及是否真正用于数值调整，前瞻观察日志保存相同特征，供后续对照实际完成结果。旧契约缓存及模型不会悄悄复用为新语义；新契约解除旧格式错误造成的功能冷却，认证及限流冷却仍保留。

2026-10-13 实际供应商探针使用四条人工构造文本，分别核对小时内预计、明天意向、带精确时间的 probably 预期、已核实父帖下的模糊时间短回复；它们不是 Tibo 的真实发言。实际 CLI 同时核对 AI 与 `--no-ai` 路径：新完成公告已被官方原文规则识别，先前 EOD 预告成为 consumed，报告只预测下一次重置。当前没有通过验证的时间预期模型，因此本轮未启用该维度的数值权重。

## 概率与模型启用

时间基础层与明确承诺的工程先验始终可运行；只有发言提取器区分 AI 与本地规则。当前不自动拟合一般消息、事故、计划进展的经验系数；旧 feature-model 实验接口保留供离线研究，正式多维路径不自动加载它。没有经过审计的负窗口不能训练，不把本轮回放当作独立验证。

### 历史承诺兑现估计

`forecast/promise-history.eli` 建立原帖与结果记录，`promise-policy.eli` 应用 `promise-history-1`。没有固定概率下限，也没有固定加分。当前承诺必须是完整官方原文、明确 global 对象、期限可解析、未兑现且未撤回；当前等待起点也必须有核实完成原文。明确 global 本身足以表明对象，不要求另写 all accounts。未明示时区的 EOD 不补时区；条件计划、banked、部分账户、否定、截断和缺失必要上下文均不纳入。

历史只使用预测时刻之前已知的原帖与事件，按发布时刻解析承诺及此前已知的父帖和计划，不把后续完成结果提供给提取器。每次只记录被解析的当前帖子，避免下一条普通发言重复记录前一承诺。同一次 global 周期内重复预告只算一次，保留第一条原期限，后续改期不能抹掉原期限的延迟；当前周期有多次预告时暂不应用数值调整。完成公告只证明其发生时刻；没有抓到更早公告不能证明它不存在。

限时预告可以跨官方自回复表达。仅从官方单帖页的类型化数据读取父帖关系，并核对可见正文、作者和 ID；父帖须已取得完整官方正文。`Day N / Reset` 属于仍有效的 full reset 计划时，可以补齐本次重置范围；否定、条件计划、手动卡或个人自动刷新不因此升级成 global。没有已核实关系的相邻帖子不能拼接。`Landing within the next 2 hours` 从该回复发布时间起算两小时上限，不依赖运行环境时区；同一关系同时交给规则和 AI，缓存身份包含关系及计划正文。

正常路径的 AI 结构化结果直接参与承诺决策：经原文校验的 promise、global、future、commitment、额度对象和可计算期限可以补入 `signals.promise`，不要求作者使用保底规则中的固定动词。只接受完整官方正文、非缺失上下文、未消耗且未被更新承诺替代的断言；AI 不给百分比，也不能撤销已经核实的后续撤回或完成公告。数值依据不足不会关闭 AI 提取，AI 仍可理解消息。`--no-ai`、快照和离线模式只运行有限规则；规则无法理解的表达保留未知，不声称具有完整语义能力。

历史记录区分按时完成、观察到期限后 48h 内完成、审计窗口内无完成、待观察和未知。只有在期限前存在核实完成公告时，才能直接记按时成功；记按时失败须有完整事件审计覆盖。期限后超过 48h 的公告不自动说成这次承诺的延期兑现。统计目标始终是未来窗口内的 global 完成公告，不把手动卡或个人自动刷新算成 global。

具体比较方法：设当前时刻距当前期限为 `δ`，每个历史案例从其期限加 `δ` 开始，分别观察后续 24h、48h。起点早于该历史承诺发布时刻的案例不比较；该阶段以前已完成的案例不进入“仍在等待”的分母。历史窗口尚未结束的案例不记失败。只合并同一时间精度（instant/deadline）与相近提前量（≤24h、≤48h、>48h）的承诺。

合格历史案例须满足：承诺、周期起点和窗口完成公告具有核实的官方原文等级；从发布到观察窗口结束的消息及事件覆盖均经过审计。`ledger.coverage` 或 `ledger.coverages[]` 记录 `from/through/audited/eventsComplete/postsComplete`，单个区间须覆盖整个案例且截至预测时刻；它是独立审计记录，不由 AI 或一次成功抓取自动生成。可比队列中存在核实不完整案例时不启用估计，不能只选择抓到的成功案例。

窗口成功次数为 `a/n`、`b/n`。用 95% Wilson 区间衡量精度，并以其中心作平滑点估计，避免少量全成功直接给 100%；[NIST 方法说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。最少 12 个合格不同周期，且两个窗口的区间宽度都不超过 40 个百分点，才应用估计。12 和 40 是保守工程门槛，不是统计定理；Wilson 中心也不代表已通过预测校准。相同期限标签不保证背景相同，跨阶段稳定性仍需前瞻验证。

满足条件时，用条件兑现估计替换两个窗口的结果，不与使用相同事件的历史基线再次叠加或取较大值；48h 不小于 24h。期限已过但尚未完成时，可以比较历史同样延迟阶段，不无限续期或冒充按时兑现。AI 不可用时仍执行规则解析和这份历史估计。

样本少、区间过宽或存在未知案例时，使用当前多维交付数值路径。`promisePolicy` 保留严格历史估计的审计结果，`forecast.dimensions` 保存实际应用的交付估计、原始基线和先验参数；`promisePrior` 是被替代的旧计算诊断。未知案例不当失败，也不只取已知成功计算兑现率；已核实的完成可用于学习延期长度。新完成或撤回停止承诺调整；逾期概率通过条件分布连续衰减，不在六小时处硬切换。公开报告照常给两个百分比，公式和参数见 [数值预测](numeric-forecast.md)。

## 缓存与失败

正式预测的维度评分通过共享网关缓存，身份含全部正文、窗口成员、核实关系、时间桶和历史输入；命中重新校验。预测结果仍有两分钟共享缓存和并发合并，不按订阅人数重新生成。所有维度的有效状态每次由程序计算，不永久保存成待兑现。

旧逐帖提取 API 与永久 post-feature 缓存仍供独立研究使用，正式预测不逐批调用它。模型超时、供应商冷却、无密钥、功能禁用、输入超预算或评分格式错误均使用本地同结构提取，不进行第二轮模型请求。正文以 UTF-8 字节上界保守计量，单次维度输入预留响应后小于1M；超限保留全部本地记录并走规则，不偷偷删掉用户要求的窗口。明确 --no-ai、离线及快照不请求模型。

搜索、状态页或新闻失败只让对应资料维度缺失，历史和帖子窗口继续计算。官方资料和历史覆盖未知不会伪装成不存在，也不会据此生成负训练标签。

## 前瞻日志与本地检查

`feature-observations.json` 保存真实完成计算的时间、证据时间、周期 ID、基线与结构化特征。最多 1000 条，至少间隔 48h，缓存命中不新增样本；离线/指定快照不写入。已经核实的官方完成公告可以登记正结果；没有经过审计的完整事件覆盖不能登记负结果。没有完整消息覆盖的记录也不能训练特征模型。

当前公开抓取不保证完整历史，因此可训练样本可能长期为零，程序不会用“没抓到”补出负例。旧经验不会直接迁移为新特征训练标签。管理员确认 `clear-experience` 时，连同旧经验备份并清空这份日志、复盘及模型产物；永久原文和逐帖事实提取不清空。

```bash
tibo forecast --json
tibo forecast --no-ai --json
tibo diagnose
tibo ai-status
```

本地 JSON/diagnostics 中查看 `structuredFeatures`、`forecast.temporal`、`forecast.dimensions`、`forecast.promisePolicy`、`forecast.promiseHistory` 和 `featureObservations`；`ai.features.signals` 包含 AI 行数、规则行数及单次任务状态。`ai.features.forecast/review.state=retired` 表示旧路径停用。公开报告仍只保留概率、参考消息和必要理由，不附这些诊断细节。

实际 CLI 试用时，用独立状态目录并将输出写到该目录外或不与业务状态文件重名的路径；尤其不能把终端输出重定向到 `ai.json`、`ledger.json` 或 `feature-observations.json`。
