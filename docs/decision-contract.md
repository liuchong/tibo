# 判断契约

## 输出契约

普通预测报告严格沿用 v1.1 区块及字段顺序：标题、结论、客观数据、概率推导、未核实项、执行摘要。不附参考站列表、表格、XML 或模板外区块。原文保留英文，每个字段单行，UTC 时间使用 `UTC MM-DD HH:mm`，标题使用北京时间。

缺失数据标记“未核实”。只有检查过对应范围确实没有记录才用“无”，同时注明范围。未来概率与实际重置状态分别输出；概率不是预言，不给买卖或囤额度建议。

## 内置规则策略 1.0

这些数字是首版程序的可审计选择，不是用户提供 skill 中隐藏的公式，也不是已校准的统计模型。

1. 全样本与 8 月起条件频率均存在时取平均，只有一个存在时使用该值。两者都为零样本则拒绝生成数值预测。
2. 未消耗的明确 global 承诺，目标落在未来 24h 或已过目标但仍在 6h 宽限内：实时主页原文下限 90%/95%，存档原文下限 75%/85%。目标在 24–48h：只提高 48h，下限分别 90%/75%。宽限覆盖通常延迟，不代表保证兑现；超过宽限不给旧承诺继续加权。
3. 近 24h 有经原文核对的 banked，且没有独立事故补偿或明确 global 承诺时，仅将 24h 乘 0.65；48h 不额外下调。只有站点观测不能触发该调整。单独发放 banked 后的等待分布重新统计（同时 global+banked 的记录不混入），不硬编码用户曾提供的 5 个样本。
4. 未消耗的 Tibo 事故补偿暗示，在没有已计权明确承诺时，实时原文增加 10/15 个百分点，存档增加 5/10 个百分点。状态页事故本身不自动产生补偿概率；同一催化不重复计权。
5. 发布/里程碑保留为证据，不自动视为 global 承诺。banked 只有明确关联到承诺才消耗承诺；最新 global 清除其之前的旧信号。
6. 结果四舍五入并限制在 0–100，保证 48h≥24h。具备仍有效的实时原帖对象+时间明确承诺时为高；活动存档承诺或补偿暗示为中；没有新信号且任一条件样本不足 20 为低。

可配置 AI 分析命令进行综合判断，保留基线、引用和判断模式供审计。程序不声称规则模式完整复现人工综合判断，也不声称模型引用校验等于事实核实。

## 证据与故障边界

- X 页面必须解析到准确作者、时间和正文。登录页、空 HTML、动态壳不算成功。近 10 条存档可能无法覆盖全部 48h，必须显示缓存及完整性限制。
- 存档全历史先核对记录数量。带原文的记录允许纠正 global/banked 分类；没有原文的历史类型仍是存档记录，无法声称已逐条核实。
- 历史 global 是公告/站点观测时间；个人额度、个人每周窗口和最终传播时间不由本程序推断。
- 交叉页仅验证可解析的 last-global 时间，站点模型概率和信号加成值都不进入判断。同源转载可能不独立；一致也不能取代原帖。
- 状态页只把近 48h 明确包含 Codex 组件的事故标记为已核实事故；缺失组件标签的事故未核实。新闻和社区转述不会升级成官方事实。
- 时间、作者、结构、历史或分析命令异常均显式失败/降级。缺少历史统计不能编造概率，但仍允许独立观测状态。
- Lark 投递结果未知不自动重试。成功报告才更新上一份报告；输出每次为独立快照。

## 验收范围

`bun run test` 覆盖条件样本边界、global/banked 时钟、原文纠错、承诺消耗、Pacific 日期与夏令时、事故独立性、固定模板、AI 引用校验、CLI 子进程和真实 MCP 客户端协议、群路由、定时时段及未知投递结果。

真实网络采集属于独立验证层，不能由测试快照替代。真实飞书长连接、应用权限及群内送达属于部署验收，不能由 SDK mock 替代。
