# 业务查询命令

命令定义只有一份：`src/commands.eli` 的 catalog。固定指令解析、帮助、参数校验和 AI 提示使用同一份列表。下面是首版用法。

| 名称 / 固定指令 | 参数 | 用途与例子 |
| --- | --- | --- |
| forecast / 预测 / 概率 / 重置 | horizon：24、48、both（默认）；noAi：布尔值，默认false | 查询未来global概率。`预测 48`、`预测 --no-ai` |
| status / 状态 | since：可选UTC ISO时间 | 查询最近global公告及是否晚于指定时间。`状态 2026-10-02T00:00:00Z` |
| posts / 发言 / 推文 / x / 原文 | limit：1–10，默认3；hours：1–168，默认48；keyword：原文子串，最多80字符；postId：可选16–20位X帖子ID | 查看Tibo的X原文，最新在前。`发言 5 reset --hours 24`；`原文 --postId 2106845241357824205`。按ID查询已采集记录时不受hours限制，不会凭ID声称采集过完整帖子 |
| history / 历史 / 公告历史 | limit：1–20，默认5；kind：global、banked、all（默认） | 查看公告历史。`历史 5 global` |
| banked / 发卡 / 卡 | 无 | 最近一次banked发卡及核实程度，强调手动使用与global时钟的区别 |
| signals / 信号 | 无 | 近48h已识别的时间承诺、暗示与发布，区分已消耗及未核实 |
| stats / 统计 | 无 | 可用global间隔样本量、平均、中位数、最短/最长与当前等待时长 |
| help / 帮助 / commands / 命令 | 无 | 查看自动生成的命令列表、参数与例子 |
| pray / 祈祷 / 上香 / 🙏 | action：offer（默认）、me、board、stats；limit：1–20，默认10 | 趣味电子上香、本人档案、匿名功德榜、会话愿力池。`pray`、`🙏`、`pray me`、`pray board 5`、`pray stats` |
| subscribe / 订阅 | 无 | 开启本人的定点私聊报告；不能指定收件人或时间 |
| unsubscribe / 退订 / 取消订阅 | 无 | 取消本人的定点私聊报告，不影响群推送或其他人 |
| subscription / 订阅状态 | 无 | 查看本人订阅状态及下一定点 |
| ask / 问答 | question：必填，最多800字符，含空格须加引号 | 一次性AI文字问答。`问答 "global和banked有什么区别？"`；不能调用工具或操作账户，未抓取的当前事件必须说明未知 |

中文和英文指令都可用，参数也可写成 `--limit 5` 等同名形式。posts的位置参数是条数、关键词；history是条数、类型；forecast是窗口；status是since。带空格的关键词使用引号。一条请求执行一个业务命令，其结果可串联文字处理管道。

## 原文、语言和文字管道

固定命令返回核心原始输出，帖子正文保留来源原文；语义提问根据消息文字和明确语言要求回复，查看帖子默认展示译文并附原文。英文提问且帖子本来就是英文时，只本地翻译固定界面标签，不重复调用翻译AI或复制相同正文。语言只从当前提问推断，不读取操作系统、环境变量、时区、用户身份或IM客户端语言。短句及混合语言可能有歧义，可显式指定translate目标。支持zh、zh-TW、en、ja、ko、fr、de、es、pt、ru、ar，中文字符没有明确要求时默认简体。

| 管道名称 | 参数 | 用途 |
| --- | --- | --- |
| translate | language：必填，例如zh、en、ja | 将前序结果翻译为指定语言，校验原有数字、百分比、UTC时间与链接，保持Markdown、命令名和参数名 |
| ask | instruction：必填，最多800字符 | 一次AI文字处理：翻译、总结、解释、针对结果问答或常识问答。依据指令文字选择语言；明确指定目标时优先遵从。`ask translate`通常推断英语，`ask 翻译成中文`推断中文 |
| original | 无 | 恢复本次业务命令的原始输出，不调用AI；不是重新抓取，也不是补全来源缺失正文 |

```sh
tibo query 'posts 2 |translate zh'
tibo posts --limit 2 '|translate zh'
tibo ask 'Show me the latest two posts'
tibo query 'posts 2 |ask translate'
tibo query 'posts 2 |translate zh |ask 用两句话解释是否构成重置承诺'
tibo query 'posts 2 |translate zh |original'
tibo status '|translate en'
tibo query 'help |translate en'
```

CLI将整个查询或单独的管道字符串加引号，避免shell解释 `|`；Lark直接发送 `@机器人 posts 2 |translate zh`。MCP使用tibo_ask的question传同一字符串。管道目录在 `src/presentation.eli` 统一定义，与业务命令列表一起提供给文字AI；增加能力需增加名字、参数校验、执行分支与帮助说明，不开放任意shell、代码或写工具。

每次最多3段、整条查询最多2400字符；在业务执行前检查管道结构、长度与隐私。内部调用遇未知名字/参数立即拒绝；人工输入可将该段标为待修复，在执行到该段时处理，已完成的步骤不重跑。每个文字AI请求最多15秒，文字处理总预算30秒；无法修复或执行失败即停止后续阶段，保留最后成功的结果并给出对应语言的通用提示。原始结果会保留在内部originalText，概率与证据结果不因文字处理改变。translate、answer、repair可独立关闭；`--no-ai` 禁止本次AI处理。固定业务命令仍可用。

管理员写操作申请、confirm及cancel禁止管道，确认ID不会送入文字AI。pray和本人订阅可对确认回复进行文字处理，主动作仅执行一次，不因处理重试重复操作。来源正文被截断时会明确标注并提供原帖链接；翻译不是新证据，AI解释也不表示承诺已兑现。ask的校验能保证格式与隐私，不能保证所有解释都正确，查询原文可直接对照。

定点推送仍为所有订阅者共享的同一份原始Markdown报告，仅北京时间09:00和21:00；不按订阅者语言生成额外报告。语言与管道处理只适用于主动交互查询。

## 人类命令错误的AI保底

`TIBO_AI_FEATURES` 添加repair后，只在真实交互入口遇到名字/参数解析失败时调用。CLI参数来自用户实际argv；Lark仅已认证人类事件开启。该标志由接入层传给内部options，不能通过命令参数、AI输出或MCP工具参数打开。其他IM接入需在验证人类消息后使用同一入口；内部业务调用、MCP、daemon、定点共享报告与分发均不启用repair。原有语义问答router独立运行，不能把内部执行错误转成保底请求。

常见语言别名cn、zh-cn、zh-CN、汉语、国语、普通话等本地映射到zh，无额外AI。未知写法或表达才请求repair，例如：

```sh
tibo query 'posts 2 |翻译'
tibo query 'posts 2 |translate 我使用的语言'
tibo query 'posts 2 |translate my language'
tibo posts --limit 两
tibo query 'pray |ask 用一句话总结 |翻译'
```

“我使用的语言”只依据当前人类提问及片段，中文表达通常得到zh，英文表达通常得到en；不看来源帖子的语言、系统locale、时区、用户身份或历史猜测。混合语言有歧义时用明确目标。status的相对日期修复可提供当前UTC业务时钟，不猜测用户时区；其他修复不带采集时间。

每次修复只发脱敏的失败片段、消息语言、允许目录，以及已识别的命令名；不发送前序正文、完整管道、错误堆栈、身份、配置、路径或密钥。已识别命令只能修复本命令参数，不得改成另一业务命令；AI的JSON再次经过同一类型、范围、权限及多余字段检查。不确定、越界、需要丢弃额外参数或扩展接口时拒绝，不任意猜测执行。无参数命令的额外参数没有合法修复目标，直接拒绝；自定义订阅时间与代他人操作仍无效。

主命令参数在业务调用前修复；管道修复在当前段进行，使用内存中的前序结果继续执行。比如pray已记录一次、ask已得到摘要，随后“翻译”才被修复，翻译输入是摘要而非重新pray或重新ask。修复失败也保留摘要，不重试已完成操作。运行中的采集/文件/API故障、权限拒绝、AI文字结果校验失败都不触发repair。

每个请求最多两次修复尝试，包含缓存命中，每次API最多10秒；修复预算总45秒，管道修复同时受剩余30秒文字处理预算限制。相同修复缓存20分钟，已成功解析的命令零repair请求。repair与其他AI任务独立熔断、统计，供应商故障仍共用暂停；不可用时保留现有结果并给通用提示。确认、取消和危险写命令不走修复，也不能通过管道绕过。

## 管理员写操作与二次确认

以下命令只有管理员可申请。普通用户的help与语义目录不显示这些命令；尝试固定指令仍会拒绝。

| 名称 / 固定指令 | 参数 | 用途 |
| --- | --- | --- |
| clear-history / 清空历史 / 重置历史 | 无 | 申请清空本地历史缓存；下一次联网采集可能重建，不删除远端公告 |
| clear-experience / 清空经验 | 无 | 申请清空已记录的预测经验及成绩 |
| reset-ai / 恢复AI / ai-reset | 无 | 申请清除AI暂停和缓存，允许重新调用 |
| confirm / 确认 | id：必填UUID | 明确执行本人在当前会话申请的动作；只接受固定指令 |
| cancel / 取消 | id：必填UUID | 取消待确认动作；只接受固定指令 |

“历史”始终只读；“重置历史”是危险写操作申请。首次申请只返回确认ID与动作说明，不修改目标数据。五分钟内发送 `确认 <ID>` 才执行；`取消 <ID>` 放弃。ID绑定申请人、会话、接入方式及动作；其他管理员不能代确认，权限撤销后不能确认，过期或已使用不能重放。

在本地配置 `TIBO_LARK_ADMIN_OPEN_IDS` 为该应用身份下的管理员open_id，`TIBO_LARK_CHAT_IDS` 为授权群；均逗号分隔。管理员身份只读取官方事件的sender_id.open_id，不接受消息文字或AI返回的身份。未配置管理员白名单则拒绝所有危险管理写操作；授权群的成员仍可记录本人的趣味祈祷。只配置自己的open_id即可实现单管理员。CLI使用安装器登记的 `TIBO_LOCAL_ADMIN_UID`，确认人必须是同一本地账户。MCP没有认证的人类身份，始终不提供写权限，也不允许调用者传入context伪造权限。

写入前在受影响状态的锁内保存本地备份，备份失败则不修改目标；确认票据先标记执行中再修改，崩溃或不确定失败不自动重试同一个ID。备份、票据与状态文件只在本地，权限0600，备份名为 `backup-<ID>.json`。恢复需在本地停止相关进程后处理，不开放群内任意文件操作。

语义模式可为管理员解析写操作申请，仍需随后明确输入确认ID。确认和取消从AI目录中排除；即使AI自行返回也会拒绝，不可代替用户确认。

## CLI 与 MCP

```sh
tibo query "发言 3 reset"
tibo ask "帮我看看最近三条X发言"
tibo ask "只用基础算法查未来48小时global概率"
tibo posts --limit 5 --hours 24 --keyword reset
tibo banked --offline
tibo stats --offline
tibo commands
tibo help
tibo ask "有哪些命令可以用，参数怎么写？"
```

CLI query和ask都先尝试固定指令，其余交给可选语义解析。业务目录中的ask为单次问答命令，可通过query中的固定指令调用而跳过router。CLI原有forecast/status/history诊断输出仍可在本地使用；加管道后使用公开业务格式，远程查询也使用公开输出格式。

MCP增加 `tibo_query`（command、args）与 `tibo_ask`（question）。例如：

```json
{"name":"tibo_query","arguments":{"command":"posts","args":{"limit":3,"hours":48}}}
```

原有三个Codex查询工具仍可用，forecast使用公开报告。业务目录中没有安装、重启、环境、配置、身份、模型或密钥查询。

## 飞书查询入口

普通查询只接受配置群中用户明确@本机器人的文字，例如 `@机器人 发言 3` 或 `@机器人 最近一次发卡是什么时候？`。群白名单和消息时效保持生效。已收到的文字含🙏时只执行一次pray，不要求@；平台是否投递未@消息取决于应用权限及群设置。点击本程序已成功发送的机器人消息上的「双手合十」🙏也可祈祷，需要另行订阅表情事件，见[Lark接入](lark.md)。

机器人私聊也可使用查询和订阅命令，无需@。危险管理操作仍限定管理员及授权群；私聊不开放管理权限。

## 定点私聊订阅

群内 `@机器人 订阅`，或机器人私聊发送 `订阅`。固定指令及语义“每天早晚私聊发我一份报告”“取消给我的定时推送”“我有没有订阅”分别对应subscribe、unsubscribe、subscription。订阅与退订只改本人状态，无需管理员或二次确认，不能提供其他收件人。

推送**有且只有北京时间每天09:00、21:00两个定点**，没有时间、时区、cron或周期参数，AI也不能设置。订阅成功仅回复状态，不立即发送预测；从下一个定点生效。错过该定点分钟不额外补发。订阅按接入平台与应用账户隔离，同一人在多个群和私聊重复订阅仍只有一份，不按群重复私聊。退订在后续发送前检查；已在发送中的消息可能无法撤回。

每个定点先由独立核心生成、持久化一份公开报告，再向群和订阅者分发完全相同的Markdown内容。采集、算法、AI分析及预测经验记录不会按人数重复；人数只影响消息API次数和分发耗时。报告不做私人定制，不含他人身份或订阅名单。订阅目的地址只在私有本地状态和消息路由参数中使用，不上传AI或放入公开内容。CLI/MCP没有IM投递身份，不能订阅或指定收件人。

## 趣味祈祷

电子香火与真实重置证据、概率、预测经验完全分开。每条pray或含🙏的消息记一次，不按表情数量叠加；带肤色的🙏也识别。15秒内重复上香记录次数，但不增加功德。每个人的称号和回复随功德变化，从试用香客、额度守望者到天庭SRE、赛博方丈；1、3、10、30、50、100、233、500、1000功德触发个人成就与文案。会话总功德到10、50、100、233、500、1000触发集体彩蛋。连续3天/7天另解锁打卡成就，日期按北京时间计算，断签重计，保留最长记录。

`pray me`查看本人档案；`pray board [limit]`查看匿名榜及本人名次；`pray stats`查看会话人数、总次数、功德与集体彩蛋。各IM、各会话及本地CLI分别统计，只公开会话内香客编号。本人标识在祈祷档案中存摘要，不公开平台用户ID、昵称或系统账户；不能替别人上香或指定别人的身份。MCP没有可信本人身份，pray返回提示，不改档案。

开启router后可以说“给重置上炷香”“查看我的祈祷档案”“看看功德排行榜”。AI只解析到同一份pray命令参数；趣味回复由核心规则生成，不额外花费AI调用。AI关闭/报错仍可使用固定指令和🙏。Lark同一人对同一条本机器人消息的🙏回应只记一次，删除重加、平台重投不刷功德；其他表情、应用操作者、其他人发的消息上的回应均忽略。

## 语义解析

在本地配置的 `TIBO_AI_FEATURES` 中加入 `router` 启用语义模式；加入translate启用语言展示，answer启用文字问答。可与其他功能任意组合。关闭router或AI不可用时，固定命令仍直接运行。各任务复用AI暂停/恢复机制，独立记录参数及输出错误；供应商级认证/余额/网络暂停会共同影响AI功能。

路由提示正文只包含命令目录、脱敏后的本次问题及用于相对日期的当前UTC。不上传群历史、发送者/群标识、配置、运行环境、文件、日志或报错。路由AI返回一个 `{command,args,language}` JSON；程序重新检查命令白名单、类型、范围、语言及多余字段，校验通过才调用业务函数；写操作随后重新检查权限，只生成确认票据。常识、概念或文字问题可选ask；自定义订阅时间、隐私或越权问题仍返回unsupported。

文字助手复用同一AI网关，只接收脱敏的当前指令、前序公开文字、目标语言及能力目录；输出仅允许 `{text}` JSON，不允许返回可执行命令。未抓取的当前事实必须标为未知，无联网、多轮工具循环、文件读取或写操作能力。总共至多一次路由加三次文字处理，普通问答通常一次路由加一次answer，固定问答只需一次answer。有效结果缓存20分钟；固定原文查询和original无需AI。

## 公开输出与隐私

飞书回复使用专门的业务格式，不发送内部result JSON、配置、模型名称、目录、用户名、主机或供应商错误。帖子只显示原文、UTC时间、核实等级及标准X原帖链接。内部报错统一替换为“查询暂时出了问题”；语义AI失败为“语义查询暂时出了问题，请使用固定指令或帮助”。预测辅助失败仍返回可用算法结果并给通用提示，不给出认证/余额/HTTP码等细节。

公开文字在最终投递前再过滤本地身份、实际凭据、路径和供应商名称。AI预测提示也只使用明确选取的公开证据字段；原始采集错误不进入提示。语义提问与缓存校验遵循同一边界。API认证Header和协议所需model字段仅用于已经配置的模型端点，飞书收件群ID仅用于消息路由；它们不进入提示正文或群消息内容。

数据来源可能漏帖，未见记录不等于证明没有发生；banked与global始终分开。个人账户实际额度不由公开公告推断。
