# 语言与管道

## 原文与回复语言

固定 `posts` 命令返回原文正文、UTC 时间、核实标签和链接。它不会因为运行机器的语言、时区或账户名称自动翻译。指定 `postId` 可以查看已知单帖。

```bash
tibo query 'posts 2'
tibo query '原文 --postId 2106845241357824205'
```

语义查询按提问文字和明确语言要求选择回复语言。语义查询帖子时，跨语言结果会保留译文与原文；原帖本来就是英语且请求英语时只调整界面文字。语言识别不保证能仅凭很短的词识别所有语言，可以显式指定目标。

```bash
tibo query '最近两条发言是什么？'
tibo query 'Show me the latest two posts'
```

## 管道语法

用一个带引号的字符串把完整查询传给程序，防止 shell 把 `|` 当作操作系统管道。

```bash
tibo query 'posts 2 |translate zh'
tibo query 'posts 2 |translate ja |ask 用两句话总结'
tibo query 'posts 2 |translate de |original'
```

每一步接收**前一步的完整公开文本输出**，包括标题、正文、核实标签和末尾说明。最多接 3 步；整段输入 ≤2400 字符，基础查询和问答指令各 ≤800 字符。

| 管道 | 参数 | 行为 |
| --- | --- | --- |
| `translate` | 目标语言必填 | 翻译当前文本的全部自然语言，保留 Markdown、数字、UTC 时间、百分比和链接 |
| `ask` | 文字指令必填，≤800 字符 | 对当前文本做解释、总结、翻译等一次性处理 |
| `original` | 无 | 恢复基础命令最初的公开输出，不需要 AI |

`original` 恢复的是基础命令输出，不是上一段结果；它不会重新采集。管理员危险操作不允许管道。文字步骤没有文件、联网、命令执行或账户操作能力。

## 翻译语言

使用合法且运行时可识别的 BCP47 语言代码，例如 `zh`、`en`、`ja`、`ko`、`de`、`mn`、`mn-Mong`、`zh-TW`。支持基础语言，以及可选文字系统和地区；不接受任意字符串或所有扩展形式。代码被接受不保证模型对该语言的翻译质量。

```bash
tibo query 'posts 2 |translate zh-CN'
tibo query 'posts 2 |translate 汉语'
tibo query 'posts 2 |翻译成日语'
tibo query 'posts 2 |ask 翻译成中文'
tibo query 'posts 2 |ask translate'
```

常见中文别名（如 cn、zh-cn、汉语）直接规范化。无法直接识别的管道名称或参数，在符合人工输入条件时才调用 `repair`。`ask translate` 根据这一步英文指令推断回复语言为英语；中文指令可以推断中文。想避免歧义和额外调用，用明确的 `translate 代码`。

## 错误输入的 AI 修复

修复是错误发生后的保底，正常固定命令不会先交给 AI 分析。CLI 和认证后的 IM 人工消息可以启用；MCP 结构化调用、内部任务、定时报告和模型自己产生的错误不启用。

- 基础命令参数解析失败时，提供出错片段和相关命令目录，校验 AI 返回的结构后再执行。
- 某一步管道不认识时，保留已经完成的基础查询和前序结果，修复当前步骤后继续。
- 不重新执行整条链，避免重复采集、重复上香或重复其他有副作用的操作。
- 已知命令的修复不能变成另一个命令；管理员操作、确认、权限拒绝和运行时/API 故障不由修复处理。

每次人工输入最多 2 次修复尝试，命中修复缓存也计数；单次最多 10 秒，修复预算截止为该次解析开始后的 45 秒，仍受当前阶段剩余预算限制。管道文字处理总预算为 30 秒，不会因为修复另起一整段预算。

## AI 失败与长度限制

`translate` 需要该功能开启；管道 `ask` 需要 `answer`；错误输入修复需要 `repair`。全关闭时仍可使用固定查询和 `original`。

翻译输入上限为 16000 字符；超限不截掉一半后冒充完整翻译。一次性问答最多接收前 10000 字符，并向模型注明截断。单次 AI 文字输出需 ≤14000 字符，最终展示限制为 15000 字符；超限或数字、链接等校验失败会保留原始结果。数字校验允许英文数量词等值变成数字，但不能增加新的百分比。

如果后续步骤失败，返回已保留的结果并附简短提示，停止后续处理；不会把供应商原始错误发给 IM。提示不等于前一步没传入全文：超时、输出截断、结构或事实标记校验失败都可能造成降级。CLI 的保留结果可能仍以成功状态返回，需同时看正文提示与本地 `ai-status`。

校验保护的是结构与关键标记，不能证明译文语义完全正确，少见语言尤其需要查看原文。[故障排查](troubleshooting.md) 说明如何查失败阶段。

## 隐私边界

模型只接收任务所需的公开业务文本、当前指令及能力目录；输入修复不发送前序查询结果。问答和翻译不会带上系统目录、系统用户、IM 身份、API key、模型配置或群历史。供应商认证头和模型请求字段是调用所需元数据，不属于发给聊天用户的内容。

内部诊断、服务管理与配置查询不能通过语义输入或管道转发。IM / MCP 输出经过公开文本过滤；不要把本地 `--json` 或诊断快照直接转给群聊。
