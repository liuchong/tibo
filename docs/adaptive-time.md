# 动态时间分布、近期节奏与重置卡

策略版本11。时间层由纯 Eliscript 计算，与 AI 是否启用无关；AI 只替换发言特征提取器，仍一次返回全部窗口。历史永久保留，安装种子只用于初始化，运行时不读取仓库历史文件。

## 概率计算顺序

```text
公开完成事实去重、排序，消费旧承诺
→ 原有四模型 + 近期节奏候选
→ 按周期长期/近期误差收缩组合
→ 双尺度日历和日内风险积分
→ 原有六窗证据、审计承诺兑现或交付先验
→ 最终24h/48h及重置卡建议
```

原四模型的计算公式、条件分母 D>当前等待、4个平滑样本、最近12个间隔和90天基础衰减保留。新候选不是对它们再乘一次提速系数。

## 第五候选：近期节奏

`adaptive-rate` 同时观察14/45/90天半衰期，长期参照仍为90天率。每尺度统计完成间隔的衰减事件质量 m、平方质量、加权暴露 E。当前尚未结束的等待 t 作为右删失暴露，衰减积分为 `C=(1-exp(-kt))/k`，k=ln(2)/半衰期。

```text
λ尺度 = (m+4) / (E+C+4/λ长期)
有效样本数 = (Σw)² / Σw²
收缩系数 = 有效样本数 / (有效样本数+8)
log(λ近期/λ长期) = 三个尺度收缩后对数率比的均值
p(h) = 1-exp(-λ近期×h)
```

4表示向长期率收缩的先验事件质量，不是假造的成功记录。新事件及持续没有新事件都会更新结果；只有一两个短间隔时影响有限。时间尺度与先验是明确工程参数，预测率、有效支持和贡献随数据变化，未编码任何固定星期、时段或“每三天重置”。未来结束记录、单纯 observed 间隔不参与，也不跨不可靠事件拼出长间隔。

## 按周期更新组合权重

回放仍逐日生成预测，并只使用该时刻之前的完成间隔。原逐时点 Brier 保留作诊断；权重使用每个重置周期内部平均误差，再跨周期计算长期均值及45天衰减近期均值。同一长周期有很多预测，不会增加有效周期数量。

至少8个可回放周期，或某候选30个已结算前瞻窗口，才使用误差偏好。学习权重正比 `1/(0.05+error)`；最终权重是该偏好与均衡权重的混合，学习份额 `n/(n+20)`。回放 error 是24h/48h长期与近期周期误差的均值；满足门槛的前瞻误差再与回放各占一半。旧前瞻记录缺第五候选时保留旧数据，不伪造其成绩。

这不是独立性或校准证明。回放依据观测账本，采集缺失仍会影响成绩；前瞻与回顾诊断分别保存。时钟不可靠时原两个条件模型停用，新候选也不使用未知等待时长。

## 双尺度日历和日内时段

采用配置的统计时区，以45/180天两个衰减尺度统计以下四维：星期、月内日期、月初/中/末、一天八个3小时段。只将有完成原文的非 observed global 用于日历计数；第一条作为观察起点，不额外记一次起点事件。

分母是实际经历的各桶时间，含当前未结束等待；UTC按15分钟边界累计，再映射到IANA日历，处理夏令时和非整小时偏移。它表示本地观测账本的暴露，不声称档案覆盖了全部网络历史。

各桶向整体率做Gamma-Poisson平滑：星期/时段先验暴露14天，日期/月阶段28天。对数率比再乘桶事件质量/(质量+3)与整体有效事件数/(有效事件数+20)。每一维按暴露量归一化为平均倍率1。短尺度向长尺度按其有效事件数/(有效事件数+20)收缩。

星期、日期、月阶段三项取平均对数倍率作为一组，再与时段组平均；最终倍率限制在2/3..1.5。没有记录的桶不会变成零概率；不启用稀疏的星期×小时交互项。样本少时接近原始基线，分布稳定且有更多记录后才逐步加强。

未来48h按小时积分：保留原四模型组合的6h累计曲线，把每段累积风险均分六份，再乘每小时的日历倍率，累积为概率。日内模式改变风险位置，不是“当前进入上午就给24h固定加分”。保留原8段兼容诊断，增加48个hourSegments。

## 时区配置

- `TIBO_TIMEZONE`：展示及默认业务日历，源码默认UTC。
- `TIBO_FORECAST_TIMEZONE`：统计和风险积分时区，未设置继承前者。
- `TIBO_SCHEDULE_TIMEZONE`：每天09:00/21:00的服务调度时区，未设置继承前者；订阅用户不能覆盖。

三个值均为IANA名称，非法值在本地报配置问题。存储、比较和期限端点始终UTC；作者原文明示PST/PDT/PT按原文及作者语境解释，不因展示设置改变。上香打卡按展示区的日期。

安装补齐缺失时区：展示/推送显式保留原安装的Asia/Shanghai，统计显式保留America/Los_Angeles，已有配置不覆盖。管理员可改为其他区后重启两个服务。改变展示区且统计区保持不变，不改变预测数值。三种区均进入共享预测缓存身份；策略升级也使旧缓存失效。

## 重置卡的粗略建议

卡建议给出一个明确方向和最关键的一句理由，概率区仍只占一行。程序按最终24h/48h分档；这些阈值是粗略的等待偏好，不是概率训练参数。

| 概率范围（按顺序判断） | 倾向 | 本地理由示意 |
| --- | --- | --- |
| 24h≥85% | 建议先等 | 短期重置机会很高，现在用卡可能与发放重叠 |
| 24h≥65% | 倾向先等 | 等一次全局发放更有希望省下一张卡 |
| 24h≥35%或48h≥60% | 略倾向先等 | 等待一次有一定价值，倾向较弱 |
| 24h≥15% | 倾向现在用 | 短期重置概率较低，不值得专门停下来等 |
| 24h<15% | 建议现在用 | 短期等到全局发放的希望更低 |

各档有三条本地短理由，实际正文带本次概率。没有可用概率才写暂不能判断。默认讨论有卡可用、正在选择用卡还是等待；不推断个人剩余额度或卡到期，不执行用卡和购买。建议不反向影响重置概率。

启用 `brief` 时，最终概率算完后至多追加一次小型文案请求：只传概率、方向、相关公开证据和当前周期状态，模型用一至两短句解释，程序保留明确行动标题。输出上限220 token、时限6秒，通常30至65字；校验方向、长度、隐私和百分比，不用本地替换润色模型文字。普通预测的六窗评分仍是一次signals请求，没有拆成多轮工具调用。signals和brief独立判断功能冷却，signals校验失败或未启用不连带禁用brief；供应商级认证、余额或限流冷却则共同遵循网关。

未启用brief、--no-ai、超时、输出无效或冷却时自动使用对应档位的本地文案，不输出错误，也不改概率。沿用网关20分钟缓存和独立brief失败冷却；共享预测缓存覆盖整份结果。渲染和订阅扇出不调用AI，当前概率变化时不会复用旧文案。

诊断保存 `forecast.cardAdvice`，含策略、决策、概率和假设；时间原始分布、先验、有效样本和小时贡献保存在 `forecast.temporal`，近期候选及组合权重保存在 `forecast.model`。报告仍只展示结论、相关原文与必要理由。
