# 对话容量与原文卸载设计

本设计固定 2026-10-14 的用户要求：单条正文不设字符上限，以每次提交的总上下文为容量边界；超出时有限摘要、保存原文文件并按需读取，不拒绝长消息，不开放 shell 或任意文件访问。此前的完整历史、摘要卸载与稳定前缀设计继续适用；16000 字符入口限制废止。归档和按需取回是本次补齐的实现，不把此前未实现的能力记成已有功能。

## 请求与会话

- 未引用：单次请求，不读取或累积旁边的聊天。超窗原文可以归档，文件仅属于该次请求，不自动成为新会话历史。
- 引用/话题：核心按已认证接入方式、账户、会话及不透明会话标识管理完整 user/assistant 历史，发送确认后追加，沿用现有串行、版本和去重机制。
- 不改变管理员白名单、二次确认、订阅或群触发权限。业务参数的类型和范围是业务契约，不因聊天容量扩大而放宽。

## 总上下文预算

[当前官方规格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)给出 1M token 窗口。默认输入目标 980000，预留输出、协议文字及计量误差；可通过 `TIBO_CHAT_CONTEXT_TOKENS` 降低摘要触发目标，最高仍为 980000。字符数不等于 token 数。

服务端返回的输入 token 数只用于未改变的已知前缀，新文本使用 UTF-8 字节数作为保守上界，不增加分词依赖。所有普通聊天、语义路由、只读计划和管道问答使用同一容量处理入口；固定任务的小型资料筛选不变。对话请求不再依靠 JSON 字符总长拒绝输入。

不超目标时保持完整原文与追加顺序，不为每一轮额外请求摘要。超出时先归档，再摘要旧历史；旧历史卸载后仍能容纳的当前正文不再压缩。当前正文或其他材料本身过大时单独归档摘要，字段语义和较小的结构化事实继续保留。

## 有限摘要与降级

摘要是独立调用，不是工具循环。一轮请求共用最多 3 次摘要机会；能够装入模型窗口的材料一次摘要，真正超出窗口的材料按容量分段。每段保留角色及内容顺序，跨段不切断 Unicode 代理对；融合结果注明是否完整覆盖。

摘要成功后从摘要继续追加，完整原文不删除。摘要失败或次数用完时保留已生成部分与文件索引，明确尚未完整摘要；未读内容保持未知，不能假装已经理解全文。AI 服务本身不可用时仍遵守既有降级、暂停和隐私规则，不泄露错误细节。过小的可配置目标也可以把摘要本身归档，用索引继续处理，而不是拒绝原请求。

每次摘要提交也要留在实际模型窗口之内。较低的 `TIBO_CHAT_CONTEXT_TOKENS` 是普通请求的摘要触发目标，摘要输入本身仍可使用实际模型窗口；不能把人工调低目标误认为提供方只有这么小的窗口。

## 虚拟原文文件与内置只读方法

原文以受限本地状态文件保存，仅包含原有脱敏对话材料。模型看到 `ctx-...` 虚拟文件 ID、材料标签和字符数，不看到系统目录、平台标识、凭据或运行配置。持久会话保存归档清单，重启后仍可取回；摘要失败也不会删除已归档内容。已有旧版本摘要无法恢复此前没有归档的原文，只能继续利用已有摘要与平台可核实资料。

`context-read` 只在本轮已提供归档时加入内部只读方法目录，不是公开管理命令：

| 参数 | 含义 |
| --- | --- |
| `fileId` | 必填，只能是当前请求/会话提供的虚拟 ID |
| `offset` | 起始字符位置，默认 0 |
| `limit` | 本次返回字符数，默认 12000，最多 24000 |
| `literal` | 可选原文子串定位，最多 200 字符；不是正则或代码 |

返回正文、实际起点、总字符数、是否找到和 `nextOffset`。片段不冒充完整原文。分页大小是单次取回预算，原文件没有这个长度限制。文件归属由程序的可信会话决定，不能由模型传入账户、目录或会话来切换归属；不能跨会话读取同样内容的文件，也不能用文件路径代替 ID。

取回接入已有一次 read 语义计划，与搜索、状态、计算等共用最多 3 项的一次只读批次，然后生成一次回答。模型不能在回答阶段再启动查询，不提供 shell、系统文件、任意 URL 或多轮工具调用。新资料查询仍优先服务当前用户问题，历史材料只辅助理解。

## 模块与验收

- `src/chat/budget.eli`：窗口预算、前缀计量及新增文本上界。
- `src/chat/archive.eli`：原文归档、虚拟文件目录、参数校验和当前范围内读取。
- `src/chat/packing.eli`：有限分段摘要与材料卸载。
- `src/chat/memory.eli`：请求组装和各阶段共用的摘要预算。
- `src/chat/store.eli`：持久摘要、归档清单、历史与确认提交。
- 命令层选择和运行固定 `context-read`；平台适配器继续只负责引用、身份和传输。
