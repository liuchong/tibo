# AI 与程序执行的边界

Tibo 的模型是按需调用的结构化助手，不是可操作主机的 agent。公开业务面没有 shell、exec、spawn、任意程序执行、任意文件读写、动态代码求值或任意网址工具。管理员身份也不会在 IM 内增加这些能力。

## 实际执行路径

模型只返回以下数据，程序重新校验后按固定方法处理：

- read：一次输入理解得到至多三个固定只读方法；全批校验后执行，不接受写操作、身份、代码或下一步任务；read-page.url 仅允许已提供的公网网页，来源、参数与请求方式经程序校验。
- router：命令目录中的 command / args / language。未知命令、额外字段、越界参数和自行携带的身份上下文均拒绝。
- repair：当前失败的命令或文字管道片段；不能追加系统步骤、修改管理命令或替人确认。
- signals / research / brief：结构化断言、逐字引用和有限解释字段；不返回正式概率或模型系数，不执行模型输出里的代码。
- translate / answer / oracle / wish / festival：文字或带引用的文字。即使文字长得像命令或脚本，也只展示，不送进命令执行器。
- trigger：有限关键词的相关度数字，仅决定候选是否继续处理；不返回命令或获得权限。
- search：两个受限查询，由程序访问固定搜索入口并获取白名单官方原页，不提供自由 fetch 或文件 URL。

对话 API 请求不提供执行工具，程序没有 `tool_calls` 分派器；finish_reason=tool_calls 的响应按不可用输出处理。模型能选择的“业务命令”和操作系统命令是两个不同接口，业务 command 永不送入 shell 或子进程。

## 固定系统与平台方法

后台安装、更新、重启与卸载仅从本地 CLI 的 service 分支进入 `src/platform/service.eli`。它使用固定的 `launchctl` 系统可执行文件、固定操作与 argv 数组，不使用 shell，不接受模型生成的程序或命令串。运行期使用已编译的业务代码；开发构建器调用也只存在于本地构建流程。

机器人接入只提供已写好的平台方法，例如发送业务报告、获取机器人信息、连接配置及查验已确认发送消息所在的会话类型。查验会话 ID 来自本应用发送回执，校验格式并调用固定 API；这不是模型可调用的通用 HTTP 方法。

业务存储确实会写祈祷档案、订阅、报告、去重账本和确认票据。这些是应用正常运行需要的固定状态操作，不接受用户或模型指定任意路径。配置与 snapshot 路径只从可信本地启动配置或本地 CLI 进入，不是 IM/MCP 查询参数。

聊天的基本信息由 `src/capabilities/read.eli` 在回答前准备：固定官方状态接口、固定搜索入口、确定性数字计算与时钟。搜索结果地址只用于引用，不是抓取参数；算术使用有长度、深度和数值限制的解析器，没有 eval 或动态执行。read 只选择封闭目录中的资料方法，answer 只看到准备好的数据，不发起工具请求；失败时程序仍能展示已有结果。

超窗对话的原文由核心保存为虚拟文件。`context-read` 只在当前请求或会话有归档时加入同一次只读方法目录，接受已提供的文件 ID、分页范围或原文子串，不接受路径、shell、代码或其他会话身份。文件 ID 即使被猜到，也不能跨归属读取。正文作为引用材料提供给最终回答，不启动多轮工具调用。详见 [容量与原文卸载设计](chat-context-design.md)。

## 管理员与确认

普通用户可自由使用查询、祈祷及本人订阅。清空历史、清空经验与恢复 AI 是程序内明确实现的管理方法：当前真实身份必须在白名单，第一步只生成票据，第二步由人明确输入 confirm ID。模型不能构造身份或确认票据，语义路由目录不含 confirm/cancel，模型返回这两项也会拒绝。

群订阅的新增和取消可由目标群群主或群管理员在本群申请并二次确认，申请、确认各自实时核实角色，确认单绑定申请人、会话、应用与五分钟有效期。这份权限仅限本群订阅，不授予任何系统管理权限；Tibo 系统管理员保留原私聊或操作群的管理入口。默认个人订阅在任何会话都操作本人。被动群 `all` 不增加管理权限或通知目标，不能由任意成员使群接收主动报告。群目标参数只接受明确群 ID 或可信当前群，不能执行系统命令、修改任意文件或自定义推送周期。

这条边界由接口与代码结构保证，不靠模型“自觉不执行危险命令”，也不新增一串针对用户措辞的危险词规则。已有隐私脱敏与参数约束继续用于保护业务数据。

## 验证与后续扩展

`tests/ai/ai-boundary.test.mjs` 拦截子进程执行函数，实际投递模型生成的 exec/service、附带 shell/伪造身份字段、合法关键词中的命令替换文本，以及 tool_calls 响应；确认它们不会到达进程执行器。管理确认与越权行为另由 admin 和 MCP 测试覆盖。

后续需要系统能力时，应先写固定目的的方法，明确输入、输出和业务权限，再决定是否允许模型选择它。不得增加 shell 参数、自由程序名、代码执行、任意路径或自由网络操作；新增 read-page 只提供固定目的的公开网页 GET 和 DOM 读取，不能自定义方法、认证、脚本或浏览器参数；安装与发布能力仍留在本地维护入口。常规功能可参考 [开发指南](development.md)，后台维护按 [运维步骤](operations.md)。

网页读取使用 Bun 原生接口；为动态页启动浏览器由固定程序配置完成，不暴露进程接口。WebView 强制新建独立 Chrome 后端、临时数据，不自动连接个人浏览器。原生 HTTP 和浏览器请求共用公网代理，每次解析所有 DNS 地址、拒绝非公网地址并固定 IP 连接；重定向与子资源不绕过该边界。页面内容始终作为非可信资料，不能安排执行或下一轮模型调用。详见 [网页原文读取](design/web-reading.md)。
