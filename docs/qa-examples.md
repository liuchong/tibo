# 跨领域问答样例

公开问题保存在 [cases.json](../examples/qa/cases.json)，按稳定 ID 记录问题、类别、参考资料和核对要点。样例只包含公开知识或人工假设，不保存私人会话、账户身份或配置。它们供实际试问和人工事实核对使用，不作为机器人提示词或预置答案。

## 实际运行

先构建，再用当前配置运行开发用试问入口：

```bash
bun run build
bun tools/qa-trial.mjs
bun tools/qa-trial.mjs --case news-space,work-timezones
bun tools/qa-trial.mjs --limit 4 --out .tibo/qa-trial/sample.json
```

这会产生真实模型和公开网络请求，使用与 CLI 相同的 `resolve-query` 和 `execute-query` 路径。最多两项并发，每项网络取消期限 65 秒；运行大量或排查慢例时，另设置覆盖整个进程树的硬截止。入口只能由开发者运行，不进入应用命令目录，不赋予模型进程执行能力。

结果默认在忽略目录 `.tibo/qa-trial/latest.json`，包含实际完整回复、耗时、最终命令、资料读取状态和公开数据。可用 `--out` 指定其他本地验收文件；不要提交包含私有问题的运行记录。程序不记录密钥、请求头、系统提示词或供应商错误正文。

`ok=true` 只表示程序完成请求。每条仍标记 `review=pending`，需要核对：是否回答所有子问题、事实是否正确、引文是否支持结论、当前数据是否足够新，以及回复是否简洁。网页抓取失败但模型诚实说明，属于成功处理失败，不能计为新闻问题已答对。

## 动态资料的检查

天气与新闻不使用永久固定答案。核对本轮取得的网页或 API 数据和读取时间；网页发布日期与读取日期分开。换一天重跑允许温度、新闻标题和日期改变。参考链接也可能变更或拒绝访问，需要重新核实，不能以旧样例证明已经获得当前正文。

## 2026-10-29 试用结果

实际运行了全部 16 条，并依据参考资料与本轮公开数据核对。发现并修复：多时间与多单位问题被直接路由后只回答第一项；城市与国家混拼导致查询为空；公网地址规则过宽导致 NASA 正文被误拒绝。受影响问题修复后再次实际试问。

最终这组问题的核心答案与核对要点一致：纽约冬夏令时分别为 13:00 与 14:00，两组容量换算都保留；悉尼匹配澳大利亚；伦敦预报与取得数据一致；NASA 返回页面最新文章日期与简短任务总结。一般知识题未为凑来源而强制搜索。

来源质量仍分别记录：食品安全问题给出了正确数值，但当次官方页面访问受限，补充来源为指南整理，不能称为本轮官方正文核实。信息核验题的完整回复仍偏长，后续可用同一问题继续比较简洁程度。其他公开页面也可能受限；没有将请求成功率当作事实准确率，也不能把这 16 个样例的结果外推为所有问题都准确。

程序自动回归另覆盖来源合并与去重、不同域名正文读取、结构化商户信息、国家过滤、负日期偏移、无 AI 算术、离线与失败路径。新增问题应继续采用公开输入和独立核对要点，先实际观察问题，再优化共用能力，不为样例写死答案。

本轮代码回归：506 项通过，架构检查通过。两者验证程序契约与既有功能，不代替上述公开知识的逐项核对。
